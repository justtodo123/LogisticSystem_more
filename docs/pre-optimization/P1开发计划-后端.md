## 3. 分阶段任务

### 阶段 P1-1：调度展示优化（P1-05 / 06 / 07 / 10）

**分支**：`backend/p1-1`  
**目标**：API 返回前端展示所需的 score、节点名称、货物/订单关联；detail 接口齐全。

| 任务 | 说明 | 编号 |
| --- | --- | --- |
| F007 score 处理 | 检查 `global_schedules.score` 计算；必要时归一化或增加 `score_display`、分项字段 | P1-05 |
| 全局方案 DTO | `GET /schedule/global/{code}` 及列表：路径含 `from_node_name`、`to_node_name`、货物描述、`order_code` | P1-06 |
| 节点调度 DTO | `GET /schedule/node-dispatch` 或 detail：聚合任务、包裹；支持按 dispatch_code / vehicle 查询 | P1-07 |
| 实体 detail | 确认 `GET /orders/{code}`、`/goods/{code}`、`/packages/{code}` 等可用；缺字段补齐 | P1-10 |
| 契约 | 编写或更新 `docs/api-contract/api-contract-p1-1.md` | — |

**自测**：

- [ ] 某全局方案 score 在 Swagger 中为可读数值或带说明字段
- [ ] 货物路径响应含节点 **名称** 不仅是 code
- [ ] 节点间调度 detail 含包裹列表与货物
- [ ] 各实体 detail 接口 200

**通知前端**：Swagger 链接 + 变更字段清单。

**联调**：与前端合并 `integration/p1-1`（或本地互拉分支），对照 P1-1 验收表 4 项。

### 阶段 P1-2：全局调度增强（P1-03）

**分支**：`backend/p1-2`  
**目标**：支持订单筛选 + 预览不落库 + 确认后正式落库。

| 任务 | 说明 |
| --- | --- |
| 扩展 `POST /api/schedule/global` | 增加 `order_codes[]`、筛选参数（status、destination 等按实现取舍） |
| 预览模式 | `preview=true`：生成方案写 draft 或内存态，**不改**订单/货物正式状态 |
| 确认接口 | `POST /api/schedule/global/{schedule_code}/confirm` 或等价路径：draft → 正式，触发 F021 与 MVP 一致状态流 |
| 查询预览 | `GET` 预览方案详情（若 draft 落库） |
| 契约 | `docs/api-contract/api-contract-p1-2.md` |

**简化方案（时间紧）**：

- `global_schedules.status = draft`；confirm 时转 `active` 并写关联表。

**自测**：

- [ ] 指定 2 个 order_code 仅调度 subset
- [ ] preview 后订单仍为 pending（或原状态）
- [ ] confirm 后订单 delivering、包裹 packed，与 MVP 一致
- [ ] 未 confirm 的 draft 可丢弃或覆盖

**联调（必须）**：

- 前端「生成预览 → 确认采用」全流程
- 确认前后分别查订单状态
- 确认后继续 F021/F005 主链路回归

### 阶段 P1-3：节点到货确认（P1-08）

**分支**：`backend/p1-3`  
**目标**：实现 [P1开发计划 §1.4](./P1开发计划.md#14-p1-08-节点到货确认已对齐) 级联规则；**不改** F013。

| 任务 | 说明 |
| --- | --- |
| `node_arrival_service` | 新服务或扩展 `simulation_service` |
| `GET /api/simulation/arrival-packages` | 按 schedule_code + node_code 查 `in_transit` 到站包裹 |
| `POST /api/simulation/confirm-arrival` | 批量 normal/exception；单事务级联（§1.4.4） |
| F005 改造 | 分配车辆时跳过 `status=exception` 的包裹 |
| deliver 改造 | 移除「批量激活该节点全部 pending_pack」；L0→L1 中间到站改由 confirm-arrival 驱动；deliver 跳过 exception |
| 回归 | MVP F013 replan、ExceptionList 相关 API **行为不变** |
| 契约 | 已有 [api-contract-p1-3.md](./api-contract/api-contract-p1-3.md) |

**自测（C/D/E/F 场景）**：

- [ ] F007+F021 → F005(L0→L1) 后，confirm：C normal、D exception → E=packed，**F=exception**
- [ ] 再次 F005：仅 E in_transit，F 仍 exception
- [ ] deliver(L1→L2)：g_1 delivered，g_2/F 仍 exception
- [ ] `POST /exceptions` + replan 仍与 MVP 一致

**联调（必须）**：

- 前端到货确认页提交后与 Swagger 断言一致
- 联调文档建议：`docs/联调反馈-P1-3-致后端.md`（可与前端互写）

## 5. 与前端协作要点

1. **P1-1**：可先给示例 JSON（含 `node_name`、`score_display`），不必等全部 endpoint 改完。
2. **P1-2**：preview 与 confirm **两个接口都就绪** 再叫联调；中间状态字段名提前对齐。
3. **P1-3**：联调前准备 **固定演示 schedule**（含 C/D/E/F 数据）；联调时逐步骤对状态。
4. **长耗时**：全局调度 preview 仍可能接近 10s，保持 timeout 友好。
5. **不做 P1-12**：manager 调 `/ai/parse` 仍可能 200；答辩口头说明即可。
