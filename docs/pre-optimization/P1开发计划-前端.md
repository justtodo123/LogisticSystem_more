## 3. 分阶段任务

### 阶段 P1-1：调度展示优化（P1-05 / 06 / 07 / 10）

**分支**：`frontend/p1-1`  
**目标**：调度工作台信息可读、可搜、可点详情。

| 任务 | 说明 | 编号 |
| --- | --- | --- |
| Score 展示 | 全局方案列表/详情：格式化 score；`el-tooltip` 说明含义 | P1-05 |
| 货物路径 UI | 折叠/下拉；搜索（货物号、订单号、节点）；节点显示 **名称** | P1-06 |
| 节点调度 UI | 调度列表折叠 + 搜索（编号、车辆）；详情抽屉（任务/包裹/路径） | P1-07 |
| EntityLink | 封装可点击 code 组件；调度页、异常页、列表页接入 | P1-10 |
| 详情页/抽屉 | 订单、货物、包裹、车辆、节点 detail 统一入口 | P1-10 |
| API | 扩展 `api/schedule.ts` 等类型定义 | — |

**Mock 策略**：用 MVP 真实数据 shape + 手工补 `node_name`、`score_display` 开发 UI。

**自测**：

- [ ] 货物路径默认不全量展开
- [ ] 搜索过滤正确
- [ ] 点击 `O_xxx` / `G_xxx` 打开详情
- [ ] `npm run build` 通过

**联调**：

- 关闭相关 Mock，对接后端 P1-1 DTO
- 与后端对照 [P1开发计划 §4.1](./P1开发计划.md#41-必做验收答辩最低线) 项 1～4

**可并行**：本阶段即可改 Login 布局、引入 CSS 变量（P1-02 初版）。

### 阶段 P1-2：全局调度增强（P1-03）

**分支**：`frontend/p1-2`  
**目标**：订单可选、预览、确认采用。

| 任务 | 说明 |
| --- | --- |
| 订单选择 UI | 工作台或弹窗：多选订单 + 简单筛选（状态、目的地） |
| 两步流 | 「生成预览」→ 展示预览方案（醒目标 `draft`/`预览` 标签）→「确认采用」 |
| 状态提示 | 预览态禁用或弱化「直接节点调度」等依赖正式方案的按钮 |
| API | `previewGlobalSchedule`、`confirmGlobalSchedule` |
| 刷新 | 确认后刷新 schedule 列表并跳转新 `schedule_code` |

**Mock 策略**：Mock preview 返回假 `schedule_code` 且不改 Pinia 中订单列表；联调前替换。

**自测**：

- [ ] 未确认前订单状态 UI 与后端一致
- [ ] 确认后进入 MVP 熟悉的全局方案流程

**联调（必须）**：

- 与后端走完整：选 2 单 → preview → 查订单 DB/UI → confirm → F021 继续
- 写联调反馈 `docs/联调反馈-P1-2-致后端.md`（可选）

### 阶段 P1-3：节点到货确认（P1-08）

**分支**：`frontend/p1-3`  
**目标**：新页完成 C/D 演示；**不改** `ExceptionList.vue` F013 逻辑。

| 任务 | 说明 |
| --- | --- |
| 新路由 | 建议 `/arrival-confirm`；侧栏菜单「节点到货确认」 |
| 页面流程 | 选 `schedule_code` → 选 `node_code` → GET 包裹列表 → 每行 normal/exception → POST 提交 |
| 异常表单 | exception 时可填 subtype、remark |
| 结果展示 | 提交后展示 `activated_downstream_packages`、`cascade_exception_packages` 等摘要 |
| 引导 | 提示下一步：节点间调度 / 模拟送达（沿用 MVP 按钮） |
| API | `api/simulation.ts` 增加 `getArrivalPackages`、`confirmArrival` |

**Mock 策略**：Mock 2 条 in_transit 包裹 C/D；提交后 Mock 返回 F=exception。

**自测**：

- [ ] 页面独立于异常管理页
- [ ] 每条包裹必须选 normal 或 exception 才能提交
- [ ] 提交成功后列表刷新或跳转提示

**联调（必须）**：

- 按 [P1开发计划 §1.4.3](./P1开发计划.md#143-演示步骤与状态预期) 完整走 5 步
- 联调后在 UI 上核对包裹/货物/订单状态（可接详情 drawer）
- 确认 MVP 异常重规划页仍正常

## 6. 与后端协作要点

1. **P1-1**：后端给字段清单后更新 `types/`；不要硬编码 SC 名称。
2. **P1-2**：preview 响应里哪些字段表示「未落库」提前对齐，UI 标签依赖它。
3. **P1-3**：联调时 **逐步点击** 并截图/记录状态；发现问题写联调反馈 md。
4. **P1-4**：纯前端 PR 可单独 merge，不阻塞后端。
5. **Mock 开关**：联调阶段确认 `VITE_USE_MOCK_*` 全关（与 MVP 阶段 8 相同）。
