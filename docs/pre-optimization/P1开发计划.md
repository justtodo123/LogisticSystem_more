### 1.1 P1 目标

在 MVP 主链路可用的基础上，完成 **答辩演示体验** 与 **调度/异常操作细化**：

```text

```

### 1.4 P1-08 节点到货确认（已对齐）

#### 1.4.1 原则

| 项 | 说明 |
| --- | --- |
| **与 MVP 关系** | **不修改** 现有 `ExceptionList` + F013 异常重规划；新增独立页面与 API |
| **页面定位** | **节点到货确认**（单包裹粒度）：模拟节点工作人员对到站包裹逐条确认「正常送达 / 异常」 |
| **核心问题** | MVP 模拟送达在 L0→L1 到站时，会 **批量激活** 该节点所有 `pending_pack` 的 L1→L2 包裹，未区分货物是否实际到站，导致「货物 exception、下游包裹仍 packed/in_transit/delivered」 |

#### 1.4.2 背景：F007 + F021 与 L0/L1/L2

全局运输前执行 F007 + F021。F021 按层级预生成包裹：

| 层级 | 节点示例 | 包裹示例 | 初始状态 |
| --- | --- | --- | --- |
| L0→L1 | n_1（L0） | C、D | `pending_pack` → F021 后 `packed` |
| L1→L2 | n_2（L1） | E、F | `pending_pack`（等货物到达 n_2 后按规则激活） |
| 目的地 | n_3（L2） | — | — |

示例数据：

- 订单 O_1 → 货物 g_1；订单 O_2 → 货物 g_2
- C 含 g_1，D 含 g_2，E 含 g_1，F 含 g_2

#### 1.4.3 演示步骤与状态预期

**步骤 1 · F007 + F021**

| 实体 | 变化 |
| --- | --- |
| n_1 包裹 C、D | `pending_pack` → `packed` |
| n_2 包裹 E、F | 保持 `pending_pack` |
| g_1、g_2 | `pending_pack` → `packed` |
| O_1、O_2 | `pending` → `delivering` |

**步骤 2 · 节点间调度（F005，L0→L1）**

| 实体 | 变化 |
| --- | --- |
| C、D | `packed` → `in_transit` |
| g_1、g_2 | `packed` → `in_transit` |
| O_1、O_2 | 保持 `delivering` |

**步骤 3 · 用户在 n_2 打开「节点到货确认」**

对到站包裹 C 选 **正常**，D 选 **异常**：

| 实体 | 预期状态 | MVP 错误行为 |
| --- | --- | --- |
| C | `in_transit` → `delivered` | ✓ |
| D | `in_transit` → `exception` | 需新流程 |
| E | `pending_pack` → `packed`（g_1 已到 n_2） | ✓ |
| F | **`exception`**（g_2 未到 n_2，不应激活） | ❌ 仍为 `packed` |
| g_1 | `in_transit` → `packed` | ✓ |
| g_2 | `in_transit` → `exception` | ✓ |
| O_1 | `delivering`（不变） | ✓ |
| O_2 | `delivering` → `exception` | ✓ |

**步骤 4 · 再次节点间调度（L1→L2）**

| 实体 | 预期 | MVP 错误行为 |
| --- | --- | --- |
| E | `packed` → `in_transit` | ✓ |
| F | **保持 `exception`，不可调度** | ❌ `packed` → `in_transit` |
| g_1 | `packed` → `in_transit` | ✓ |
| g_2 | 保持 `exception` | ✓ |
| O_1 | `delivering` | ✓ |
| O_2 | `exception` | ✓ |

**步骤 5 · 模拟送达（L1→L2）**

| 实体 | 预期 | MVP 错误行为 |
| --- | --- | --- |
| g_1 | `in_transit` → `delivered` | ✓ |
| g_2 | 保持 `exception` | ✓ |
| F | **保持 `exception`** | ❌ `in_transit` → `delivered` |

#### 1.4.4 状态级联规则（实现必遵）

```text
节点到货确认（正常）— 对包裹 P 到站节点 N：
  P: in_transit → delivered
  P 内每件货物 G：
    若 G 未到订单目的地 → G: in_transit → packed
    若 G 已到订单目的地   → G: in_transit → delivered
  对 G 在 N 的下游预生成包裹（F021、from_node=N、goods_items 含 G）：
    若 G 为 packed → 对应包裹 pending_pack → packed
  订单：若该订单全部货物均为 delivered → completed；否则 delivering 不变

节点到货确认（异常）— 对包裹 P：
  P: in_transit → exception
  P 内每件货物 G：in_transit → exception
  对 G 的下游预生成包裹（含 G 的 L1→L2 等）：pending_pack/packed → exception
  订单：若任一货物 exception → delivering → exception

F005 节点间调度：
  仅 status=packed 且非 exception 的包裹可分配车辆
  exception 包裹不得进入 in_transit

模拟送达 deliver：
  跳过 status=exception 的包裹与货物
  不得将 exception 货物/包裹更新为 delivered
```

#### 1.4.5 接口与页面（概要）

详见 [api-contract-p1-3.md](./api-contract/api-contract-p1-3.md)。

| 端 | 内容 |
| --- | --- |
| **前端** | 新菜单「节点到货确认」；选方案 + 节点 → 列出 `in_transit` 且 `to_node=该节点` 的包裹 → 每条选正常/异常 → 提交 |
| **后端** | 新服务 `node_arrival_service`（或扩展 simulation）；单事务级联更新；可选写 `exception_events` 审计（**不强制触发 F013 replan**） |
| **MVP 改造点** | `simulation_service.deliver_packages` 中「批量激活 pending_pack」改为 **按货物级联**；F005 分配前过滤 `exception` |

| 8 | 登录页与主界面视觉明显优于 MVP | P1-4 | ✅ |

### 4.2 答辩演示脚本建议（约 6～8 分钟）

1. **登录页** → 展示 P1-02 美化
2. **筛选订单** → 生成 **预览** 全局方案 → **确认采用**（P1-03）
3. 查看方案 **评分** 与 **货物路径**（搜索、节点名、点详情）（P1-05/06/10）

5. **节点到货确认**（n_2：C 正常、D 异常）→ F 为 exception（P1-08）
6. 再次 **节点间调度 / 模拟送达** → F、g_2 保持 exception（P1-08）
7. （选做）地图 / AI 解释 / 方案对比 — 有时间则演示
