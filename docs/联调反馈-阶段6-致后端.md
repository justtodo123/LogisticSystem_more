### 分阶段演示脚本实测（`demo_mode=false`）

1. 全局调度 → 节点间调度：批次直接 `l0_l1_done`，30 个包裹 `in_transit`
2. 按车送达 1 个 + 全部送达 29 个 → 包裹 `delivered`，批次仍 `l0_l1_done`
3. 再次节点间调度 → 批次 `completed`
4. 包裹列表/API：`package_code` 单包裹送达可用（第二次调度后尾段 `in_transit`）

### P1 建议（非阻塞）

| 项 | 说明 |
|----|------|
| `deliver {}` 无 `batch_code` | 处理**库内全部** `in_transit` 包裹；多批次并存时一次「全部送达」影响面大；答辩演示建议单方案单批次 DB |
| 批次 `l0_l1_done` 语义 | 首次 `node-dispatch` 后即 `l0_l1_done`（表示 L0→L1 **调度**完成），与前端 Mock 的 `pending` 不同；`completed` 来自**第二次** `node-dispatch`，非第二次 deliver |
| ~~Dashboard `canDeliver`~~ | **已修复**（`96cb4c6` 后 `loadBatchDetail`；后续 `align batch states`）：`completed` 时若批次内仍有 `in_transit` 包裹，Dashboard 送达按钮保持可用 |
