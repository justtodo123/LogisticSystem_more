## 快速配置流程

### 1) 后端（最小可用）

```bash
cd src/backend
cp .env.example .env.dev
# 编辑 .env.dev，填写 JWT_SECRET（至少 32 位随机字符串）
```

可选：如需 AI 功能，填写 `DEEPSEEK_API_KEY`。

#### 数据库 URL 与迁移

- 应用运行时和 Alembic 共用 `settings.DATABASE_URL`，不要另设迁移专用 URL。
- 相对 SQLite 路径以执行命令时的后端工作目录解析；推荐先 `cd src/backend`。
- 新库或已确认安全的 Alembic managed 库，在启动/初始化数据前显式运行 `python -m alembic -c alembic.ini upgrade head`。
- 应用 startup、Uvicorn worker 和请求处理均不执行 DDL。
- 任意旧 SQLite 先备份并运行 `python scripts/migrate_sqlite.py classify <source>`；合法旧库用 `upgrade-copy <source> <target>`，与当前 ORM 完全一致的无版本库才可用 `adopt-copy <source> <target>`。源文件不原地修改，未知结构停止处理。

### 2) 前端（最小可用）

```bash
cd src/frontend
cp .env.example .env.local
# 默认全部 VITE_USE_MOCK_*=true，可独立启动前端
# 联调时逐个改为 false 关闭 Mock
```

### 3) Docker 部署

`docker-compose.yml` 使用 `${JWT_SECRET:-change-me-in-prod}` 语法提供默认值。生产部署时通过 `docker-compose.override.yml`（已 gitignore）或环境变量注入真实密钥。Compose 的一次性 `migrate` 服务与 backend 共用 `DATABASE_URL` 和数据卷，并运行 `python scripts/release_migrate.py`：fresh SQLite 可创建；现有 SQLite 只有已处于当前 head 且 schema parity 通过才放行；旧版、漂移或未知结构会 fail closed，必须先用复制迁移工具生成并核验替代文件。只有门禁成功，backend 才启动。生产密钥和生产数据库 URL 必须同时注入 `migrate` 与 `backend`（可用 YAML anchor 或 override 同步配置），避免迁移目标与应用目标分叉。
