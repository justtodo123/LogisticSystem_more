## API 响应格式

### 业务成功

```json
{
  "code": 0,
  "message": "success",
  "data": { ... },
  "meta": { ... }
}
```

- `data`：业务数据（单对象/列表/分页结构）
- `meta`：可选元数据（`degraded`/`degraded_reason`/分页 `total` 等）

### 分页列表

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "items": [...],
    "total": 150,
    "page": 1,
    "page_size": 20
  }
}
```

默认 `page=1`、`page_size=20`，`page_size` 最大 200。`GET /api/routes` 与订单等列表一样把 `page/page_size` 放在 `data` 中；非法分页参数返回 `code=40000`。

### 业务错误与 HTTP 错误

对外唯一形状是 `{code, message, data, meta}`。错误响应的 `data` 固定为 `null`。

```json
{
  "code": 40400,
  "message": "资源不存在",
  "data": null,
  "meta": {}
}
```

- HTTP status 表达传输语义：401 / 403 / 404 / 409 / 422 / 500 / 504。
- 业务 `code` 表达领域语义，来自 `src/backend/core/error_codes.py` 的 `ERROR_REGISTRY`。
- 两者不得互相替代：不能把 HTTP 404 当成业务码，也不能把 `40901` 再包进 `{detail: ...}`。
- 禁止再对外返回 `{ "detail": "..." }`。旧 `HTTPException.detail` 只作为内部兼容输入，由全局 handler 转成上述 envelope。
- 部分存量路由仍返回 HTTP 200 + 非 0 `code`；新代码不得继续扩散这套语义，迁移边界见 [R2-04A 错误迁移清单](../My_doc/plan_todo/04A-error-migration-inventory.md)。

校验失败示例：

```json
{
  "code": 40000,
  "message": "参数校验失败",
  "data": null,
  "meta": {
    "errors": [
      {"loc": "body.count", "type": "int_type", "msg": "Input should be a valid integer"}
    ]
  }
}
```

`meta.errors` 只保留裁剪后的 `loc` / `type` / `msg`，不回显原始 input、SQL、DSN、Token 或 traceback。

### AI/外部服务降级

```json
{
  "code": 0,
  "message": "success",
  "data": { "explanation": "AI服务暂时不可用，请稍后重试" },
  "meta": {
    "degraded": true,
    "degraded_reason": "AI服务暂时不可用"
  }
}
```

> 降级时 `code` 仍为 `0`（成功），前端根据 `meta.degraded` 判断是否展示降级提示。`degraded_reason` 只能使用安全公开文案，不能回传异常原文。

## 错误码体系

错误码常量与公开定义在 `src/backend/core/error_codes.py`。新代码必须引用符号名，禁止硬编码数字。

| 范围 | 含义 | 示例 |
|------|------|------|
| `0` | 成功 | - |
| `40000-40021` | 参数/历史业务错误 | `40000` 参数校验失败；`40001` 订单不存在（历史编号，HTTP 仍为 404） |
| `40100-40101` | 未登录 / Token 过期 | HTTP 401 |
| `40300-40301` | 权限不足 / 审计拒绝 | HTTP 403 |
| `40400` | 通用资源不存在 | HTTP 404 |
| `40900-40905` | 冲突/并发资源 | `40901` 状态冲突；`40902` 幂等处理中；`40903` 幂等载荷不一致；`40904/40905` 业务编号分配异常 |
| `41300` | 请求体过大 | HTTP 413 |
| `42900` | 登录限流 | HTTP 429 |
| `50000-50001` | 内部错误 / 数据库不可用 | HTTP 500 |
| `50400` | 请求超时 | HTTP 504 |

`40901` / `40902` / `40903` 的 owner 分别是 R2-01、R2-02、R2-02；后续卡不得另起一套数字或 JSON 形状。

### DomainError 与全局映射

- 新代码抛 `DomainError(CODE_*)`。HTTP status、默认公开 message 从 registry 读取。
- 可选 `meta` 只允许 `errors` / `retry_after` / `request_id` / `trace_id` / `task_id`。
- `cause` 与 `log_context` 只进日志，不进响应。
- 旧 `HTTPException.detail` 为字符串时，映射为该 HTTP status 的安全默认文案；401 且含“过期/expired”时映射 `40101`。
- `detail` 为字典时，只接受已登记且与 HTTP status 一致的 `code`；未知键丢弃。
- 数据库异常对外固定 `50001`；未处理异常对外固定 `50000`。
- 需要保留的协议头只有 `WWW-Authenticate`、`Retry-After`、`X-Request-Id`、`X-Trace-Id`、`X-Task-Id`。

### 数据库 Session

`get_db` 约定：正常 `yield`；异常先 `rollback` 再重新抛出原异常；`finally` 关闭 Session。rollback 自身失败时只记录异常类型，不记录 rollback traceback，也不覆盖原始业务异常。

### 使用方式

```python
from core.error_codes import CODE_ORDER_NOT_FOUND
from core.errors import DomainError

raise DomainError(CODE_ORDER_NOT_FOUND)
```

## 鉴权体系

| 级别 | 依赖函数 | 角色要求 | 使用场景 |
|------|----------|----------|----------|
| 公开 | 无 | 无 | 登录、健康检查、Prometheus metrics |
| JWT | `get_current_user` | 任意已认证用户，具体写权限仍由后端 permission dependency 决定 | 列表查看、详情查看及按权限划分的业务操作 |
| 细粒度权限 | `require_permission(...)` | `admin`、`dispatcher`、`viewer`、`warehouse_operator`、兼容 `manager` 按映射授权 | 用户管理、调度、确认、导出、到货确认等写操作 |
| ERP | API Key；未配置时 JWT fallback | fallback 要求已认证的 dispatcher/admin | `/api/erp/orders` |

`core/permissions.py` 中还定义了 `require_role(*roles)` 和 `require_permission(*permissions)` 工厂函数，可按需扩展更细粒度权限。

## 前端约定

- **组件名**：PascalCase，多词（`VehicleTaskTable` 而非 `TaskTable`）
- **文件名**：kebab-case（`vehicle-task-table.vue`）
- **Composable**：`use*` 命名（`useGlobalSchedule`），返回 ref/reactive + 方法
- **API 封装**：每个领域一个 `api/<领域>.ts`，通过 `api/request.ts` 的 axios 实例发请求
- **类型**：`types/<领域>.ts`，前后端字段对齐

## 数据库约定

- **主键**：自增 `id` (Integer)
- **业务编码**：`xxx_code` 字段（如 `order_code`/`vehicle_code`），唯一索引
- **时间戳**：`created_at` + `updated_at` (DateTime)，ORM 自动管理
- **删除**：物理删除（不做软删除），`ondelete="CASCADE"` 处理级联
- **迁移**：Alembic `versions/` 目录，每次模型变更生成新迁移
