## 1. 文档说明

### 1.1 为何新建 V2.8，而非直接改 V2.7

| 方式 | 说明 |
| --- | --- |
| **保留 V2.7** | 立项与 MVP 开发前的**原始需求基线**（2000+ 行，含多轮澄清历史），不宜覆盖 |
| **新建 V2.8** | 记录 **MVP + P1 迭代完成后** 的实际交付范围、实现状态、与 V2.7 的差异 |

V2.7 中「P1」多指 **AI 模型算法（F007-1/F005-1/F006-1）** 及部分 AI 助手；项目组在 2026-06-09 确认的 P1 迭代以 **答辩体验与调度操作细化** 为主（见 [P1功能概览 §2](../P1功能概览.md#2-项目组确认范围2026-06-09)），**二者不完全等同**。本交付版以项目组确认范围为准。

### 1.2 产品定位（不变）

教学实训项目（华中科技大学软件学院，2026），可演示的智能物流调度平台：订单 → 全局调度 → 节点间调度 → 路径规划 → 模拟送达 → 异常重规划 → AI 助手。

### 3.3 F015 方案解释（交付细节）

**接口**：`POST /api/ai/explain`

**请求**：`{ schedule_code }` 或 `{ batch_code }`（v1 UI 仅传 `schedule_code`）

**响应**：`explanation`、`key_decisions[]`、`potential_risks[]`、`suggestions[]`；支持 `meta.degraded`

**前端**：Dashboard AI 助手 →「方案解释」→ 抽屉展示；契约见 [api-contract-p1-5.md](../api-contract/api-contract-p1-5.md)

**验收标准（对照 V2.7 F015，已实现）**：

- [x] 用户在调度工作台选中方案后点击「方案解释」
- [x] 系统将方案数据组装后调用 DeepSeek（或降级模板）
- [x] 侧边栏/抽屉展示解释、关键决策、风险、建议
- [x] DeepSeek 不可用时 `meta.degraded=true` 且有提示

### 3.4 节点到货确认 P1-08（交付细节）

**页面**：`/arrival-confirm`

**原则**：独立页面与 API；**不修改** MVP `ExceptionList` + F013 重规划逻辑

**核心验收**：C 正常、D 异常 → 下游包裹 F 及货物 g_2 状态级联为 exception，且不可被误调度为 in_transit

契约：[api-contract-p1-3.md](../api-contract/api-contract-p1-3.md)

### 3.5 订单导入（演示增强）

**接口**：`POST /api/orders/import`（MVP 已有）

**演示资源**：仓库根目录 [`orderdata.xlsx`](../../orderdata.xlsx)

**必填列**：`destination_node_code`、`time_window`、`goods_name`、`goods_type`、`weight`、`volume`

## 4. 与 V2.7 的主要差异摘要

| 维度 | V2.7 规划 | P1 交付版实际 |
| --- | --- | --- |
| P1 重点 | AI 模型算法 + 全量 AI 助手 | 体验优化 + 调度细化 + 到货确认 |
| 全局调度 | 直接生成方案 | 增加 preview → confirm 两步（P1-03） |
| 权限 | manager 对 parse 等有限制 | P1-12 未做，答辩可口头说明 |
| 模拟送达 | 契约含 status/batch 等 | P1-13 未做，仍用单包裹 deliver |
| AI 助手 | F015/F016/F017 均 P1 | F015 ✅；F016/F017 后端 ✅、前端占位 |
| 演示数据 | 50 条订单等 | `init_demo_data` 100 订单；**不预置** GlobalSchedule |

## 6. 已知限制（答辩说明）

1. **P1-12**：`manager` 调用 `POST /api/ai/parse` 等权限未严格 403
2. **P1-13**：无 `simulation/status`、`deliver-batch`
3. **F016/F017**：后端已实现，前端「方案审查」「异常分析」仍为占位
4. **init_demo_data**：不创建已确认全局方案，演示前需 preview+confirm 或 AI draft
5. **DeepSeek**：无 API Key 时 explain 走 degraded，非真实 LLM 文案

## 7. 答辩演示脚本（约 6～8 分钟）

1. 登录页（P1-02）
2. 订单管理 → 导入 `orderdata.xlsx`（可选）
3. 调度工作台 → 筛选订单 → 预览 → 确认采用（P1-03）
4. 查看评分、货物路径、节点调度（P1-05/06/07/10）
5. 节点到货确认：C 正常、D 异常（P1-08）
6. 再次调度/送达，验证异常不可 in_transit
7. （选做）AI 方案解释（F015）

详见 [P1开发计划 §4.2](../P1开发计划.md#42-答辩演示脚本建议约-68-分钟)、[README.md](../../README.md)
