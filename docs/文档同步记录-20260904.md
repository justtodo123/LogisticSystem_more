## 3. 核验口径

### API 与路由

在后端环境中只读导入 `main:app`，检查 `app.openapi()["paths"]`、`app.routes`、HTTP method/path 去重及 `include_in_schema=False` 路由；确认 `GET /api/health`、`GET /metrics`、`PATCH /api/users/{username}` 存在。公开清单按运行时 OpenAPI 统计，FastAPI 文档路由和非公开调试路由不混入统计。

### 配置、角色与错误

以 `Settings.model_fields` 对照环境变量文档；以 `core/permissions.py`、种子脚本和前端 Mock 配置核对 `admin`、`dispatcher`、`viewer`、`warehouse_operator` 及兼容 `manager`。以 `ERROR_REGISTRY` 核对 code、HTTP status 和公开消息。外部错误统一为 `{code,message,data,meta}`，错误 `data` 为 `null`；`HTTPException.detail` 仅是内部兼容输入。

### 迁移、并发与恢复

文档按代码和实验记录核对 Alembic 单 head、CAS、数据库幂等记录、fingerprint/token、原子号段、Saga lease/outbox 和 stale-token fencing；不把 Redis 当核心正确性来源，不宣称 exactly-once。

### 部署与安全发布

核对默认 SQLite Compose 与 P1 PostgreSQL 16 + Redis 7 + 双 HTTP worker + outbox worker 拓扑的区别。镜像发布按“build（不推送）→ SBOM → Trivy → policy → artifact → SHA tag → latest”描述；CD 33826520856 通过、`blocked=[]`、`exception=[]`，但不等于生产部署。

### 链接

对纳入范围的 Markdown 相对链接和当前文档锚点做路径检查。历史 README 只修复可确定的机械性路径错误，不批量重写历史正文；外部 URL 不作为本地文件存在性判断。
