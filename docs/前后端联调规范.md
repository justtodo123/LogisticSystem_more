# 前后端联调规范

> 最后更新：2026-09-04（R2 冻结后联调口径）

## 开发模式

系统支持**全 Mock 开发**，前端可在后端未启动时独立运行：

- 默认全部 `VITE_USE_MOCK_*=true`（前端 `.env.example` 模板）
- 联调时逐个关闭对应 Mock 开关 → 重启 Vite → 验证前后端数据一致

## Mock 开关清单

| 开关 (`VITE_*`) | 默认值 | 控制功能 | 对应后端端点 |
|------|--------|------|------|
| `VITE_USE_MOCK_AUTH` | `true` | 登录认证 | `/api/auth/*` |
| `VITE_USE_MOCK_BASIC_DATA` | `true` | 订单/货物/包裹/车辆/司机/节点 CRUD | `/api/orders` `/api/vehicles` 等 |
| `VITE_USE_MOCK_SCHEDULE` | `true` | 全局调度方案/批次 | `/api/schedule/*` |
| `VITE_USE_MOCK_NODE_DISPATCH` | `true` | 节点调度明细 | `/api/schedule/batches/*` |
| `VITE_USE_MOCK_ROUTES` | `true` | 路线坐标（地图渲染） | `/api/routes/*` |
| `VITE_USE_MOCK_SIMULATION` | `true` | 模拟送达/到货确认 | `/api/simulation/*` |
| `VITE_USE_MOCK_EXCEPTIONS` | `true` | 异常事件/重规划 | `/api/exceptions/*` |
| `VITE_USE_MOCK_AI` | `true` | AI 助手（解析/解释/审查/异常分析/建议闸门） | `/api/ai/*` `/api/ai/suggestions/*` |
| `VITE_USE_MOCK_NOTIFICATIONS` | `true` | 通知配置/测试 | `/api/notifications/*` |

## 联调步骤

### 1) 准备工作

```bash
# 终端1：启动后端
cd src/backend
cp .env.example .env.dev
# 编辑 .env.dev 填写 JWT_SECRET（至少 32 位随机字符串）
python -m alembic -c alembic.ini upgrade head  # 显式迁移 schema
python scripts/init_demo_data.py  # 完整 Demo；会清理并重建演示数据
# 或：python scripts/init_users.py # 仅创建/补齐用户，二者不要连续执行
uvicorn main:app --reload --port 8000

# 终端2：启动前端
cd src/frontend
cp .env.example .env.local
npm run dev  # 默认 VITE_USE_MOCK_*=true，可独立运行
```

> `init_demo_data.py` 只能用于 disposable 的本地/演示数据库，禁止对生产库或需要保留数据的开发库执行。

### 2) 逐步关闭 Mock

按依赖顺序逐个关闭：

1. `VITE_USE_MOCK_AUTH=false` → 验证登录能获取 JWT
2. `VITE_USE_MOCK_BASIC_DATA=false` → 验证 CRUD 列表/详情/创建/编辑
3. `VITE_USE_MOCK_SCHEDULE=false` → 验证调度方案创建/确认
4. 依次关闭 `NODE_DISPATCH` → `ROUTES` → `SIMULATION` → `EXCEPTIONS` → `AI` → `NOTIFICATIONS`

每关闭一个开关后重启 Vite，在对应页面确认数据来自真实后端。

### 3) 完整联调验证清单

| 功能 | 操作 | 验证点 |
|------|------|--------|
| 登录 | admin / 123456 | 获取 JWT，跳转首页 |
| 订单 | CRUD + 导入 | 分页/Excel 导入/列映射 |
| 调度 | 创建方案 → 确认 | draft→active 状态流转 |
| 路线 | 查看路线地图 | AMap 真实渲染或降级 SVG |
| 模拟送达 | 点击送达 | 包裹状态变化，路线进度更新 |
| 异常 | 创建异常 → 重规划 | 3 策略选择，差异报告 |
| AI 助手 | 自然语言输入 | 解析→确认/拒绝 建议 |
| 报表 | Dashboard 查看 | 4 KPI 卡片 + 图表 |
| 导出 | 导出订单/调度 | xlsx/csv 下载 |
| 通知 | 设置渠道 → 测试 | 测试按钮返回结果 |

## API 响应格式

前后端统一响应格式（见[规范说明](07-规范说明.md)）：

```json
// 成功
{ "code": 0, "message": "success", "data": { ... }, "meta": {} }

// 错误
{ "code": 40000, "message": "参数校验失败", "data": null, "meta": {} }

// 带降级信息（AI/外部服务）
{ "code": 0, "message": "success", "data": { ... }, "meta": { "degraded": true, "degraded_reason": "..." } }
```

## 常见问题

| 现象 | 原因 | 解决 |
|------|------|------|
| 前端 401 | JWT 过期或未登录 | 重新登录 |
| 前端 403 | 角色权限不足 | 用具备对应 permission 的账号验证；UI 隐藏不是安全边界 |
| 页面白屏 | Vite 代理未配置 | 检查 `vite.config.ts` 的 `/api` 代理指向 `localhost:8000` |
| AI 返回降级 | DEEPSEEK_API_KEY 为空 | 填写 `.env.dev` 中的 Key |
| 地图只显示折线 | VITE_MAP_API_KEY 为空 | 填写 `.env.local` 中的 Key |
| 通知测试失败 | SMTP/Webhook 未配置 | 确认 `.env.dev` 中对应字段 |
