## 1. 目标与范围

### 1.1 MVP 目标

构建**可演示、可验收、核心链路跑通**的智能物流调度平台，完成以下闭环：

```text
订单管理 → 货物管理 → F007 全局调度 → F021 打包
    → F005 节点间调度 → F006 路径规划 → F010 路线可视化
    → 异常重规划演示
```

### 1.2 团队分工

| 角色 | 人员 | 主责 |
| --- | --- | --- |
| **后端** | 同学 A | FastAPI、数据库、调度算法、API、演示数据、DeepSeek 接入 |
| **前端** | 同学 B | Vue 3 页面、调度工作台、SVG 可视化、权限路由、接口对接 |

### 1.3 协作原则

- 每个阶段**开始前**：后端先输出本阶段接口契约（OpenAPI）；前端可用 Mock 并行开发。
- 每个阶段**结束时**：前后端联调，对照架构文档主链路打勾，通过后再进入下一阶段。
- 开发中若与架构有偏差，以**可演示优先**，事后同步更新架构文档。
- 版本管理按 [Git协作规范.md](./Git协作规范.md) 执行：阶段内 push 各自分支，联调通过后 PR 合并 `main`。

### 1.4 本期不做

| 类别 | 内容 |
| --- | --- |
| AI 模型训练 | DQN / MLP+LSTM 推理与训练 |
| 运营统计 | F018–F020 看板与报告 |
| 地图服务 | 高德/百度交互式地图 |
| 可视化增强 | Canvas 轨迹动画（F011） |
| 基础设施 | 微服务、消息队列、Kubernetes |
| P1 功能实现 | 方案对比、AI 解释/审查/异常分析（仅保留占位入口） |

## 3. 分阶段开发内容

### 阶段 0：工程初始化

**阶段目标**：搭建前后端工程骨架，完成基础联调环境。

| 后端 | 前端 |
| --- | --- |
| FastAPI 项目骨架（`main.py`、目录结构） | Vue 3 + TypeScript + Vite 脚手架 |
| SQLite + SQLAlchemy 2.0 + Alembic 配置 | Element Plus + Pinia + Vue Router |
| `.env.example`、`algorithm_config.json` 占位 | 基础布局（顶栏 / 侧栏 / 内容区） |
| `GET /api/health` 健康检查 | Axios 封装（BaseURL、拦截器） |
| CORS 配置 | Vite 开发代理指向后端 8000 |

**阶段产出**：

- [ ] 后端 `uvicorn main:app --reload` 可启动
- [ ] 前端 `npm run dev` 可启动
- [ ] 前端能成功请求健康检查接口

### 阶段 1：认证与权限

**阶段目标**：实现登录与基于角色的访问控制。

| 后端 | 前端 |
| --- | --- |
| `users` 表 Alembic 迁移 | 登录页 UI |
| 预置账号种子（dispatcher / manager，bcrypt） | 登录表单与错误提示 |
| `POST /api/auth/login` | Token 存储（Pinia + localStorage） |
| `GET /api/auth/me` | 请求头自动携带 `Authorization: Bearer` |
| JWT 签发与校验（24h 过期） | 路由守卫（未登录跳转登录页） |
| RBAC 依赖注入（manager 禁止写操作） | 按角色跳转默认页 |

**阶段产出**：

- [ ] dispatcher 登录后进入调度工作台，可写
- [ ] manager 登录后进入只读视图，写操作返回 403
- [ ] Token 过期后自动跳转登录页

**阶段产出**：

- [ ] 可维护订单、货物、包裹、车辆、司机、存储中心、分拣中心

### 阶段 3：全局调度（F007 + F021）

**阶段目标**：实现全局调度算法与自动打包，结果可查询展示。

| 后端 | 前端 |
| --- | --- |
| F007 传统算法（规则评分 + 启发式） | 调度工作台页面（第一版） |
| 硬约束：1 级分拣中心容量、同订单汇聚、存储时长 | 「生成全局调度」按钮 |
| F021 打包：L0→L1 按节点对、L1→L2 按订单 | 历史方案下拉列表 |
| `global_schedules` 写入（含 version 字段） | 方案摘要卡片（距离、时间、货物数、评分） |
| `packages` 批量生成 | 「查看详情」异步加载侧边栏 |
| `POST /api/schedule/global` | 货物路径详情展示 |
| `GET /api/schedule/global`、`/{schedule_code}` | 无解 / 失败业务错误提示 |
| 调度后订单 / 货物 / 包裹状态更新 | — |

**阶段产出**：

- [ ] 点击生成全局调度，10 秒内返回结果
- [ ] 数据库有 `global_schedules` 和 `packages` 记录
- [ ] 前端可查看方案摘要与货物路径详情

**对应需求**：F007、F021、F008（摘要部分）

### 阶段 4：节点间调度（F005）

**阶段目标**：实现两次串行的层级间调度，支持批次管理与司机分配。

| 后端 | 前端 |
| --- | --- |
| F005 传统算法（规则评分 + 启发式） | 「生成节点间调度」按钮 |
| 第一次：L0→L1；第二次：L1→L2（第一次失败则不执行第二次） | 批次列表与详情页 |
| `dispatch_batches` 批次管理与状态机 | 车辆任务列表（from / to / package_codes） |
| `node_dispatches` 写入（含 level_phase） | 司机与车辆关联信息展示 |
| 同节点空闲司机自动分配 | demo_mode 开关（课堂演示） |
| `demo_mode` 跳过 L1 等待 | 失败提示（无包裹 / 无车辆 / 无解） |
| `POST /api/schedule/node-dispatch` | — |
| `GET /api/schedule/batches`、`/{batch_code}` | — |
| 包裹 `dispatch_id` 关联更新 | — |

**阶段产出**：

- [ ] 一次操作生成完整 `dispatch_batches`，含两次 F005 结果
- [ ] 每辆车有任务列表和分配的 driver_code
- [ ] 硬约束满足：载重不超限、包裹不重复不遗漏

**对应需求**：F005、F008（节点间调度部分）

### 阶段 5：路径规划与路线可视化（F006 + F010）

**阶段目标**：为每辆调度车辆生成路径，前端 SVG 静态图展示。

| 后端 | 前端 |
| --- | --- |
| F006 Haversine + 2-opt 路径规划 | SVG 路线可视化组件 |
| 为 node_dispatches 每辆车自动生成 routes | 车辆卡片，点击加载路线 |
| `routes` 表写入（route_segments JSON） | 节点标记（红）、包裹点（蓝）、路线连线 |
| 里程 / 时间 / 碳排放计算 | 多车路线（最多 10 辆，颜色区分） |
| `GET /api/routes/by-vehicle/{vehicle_code}/coordinates` | 点击包裹点 → 侧边栏详情 |
| `GET /api/routes`、`/{route_code}` | 路线图缩放 / 自适应 |

**阶段产出**：

- [ ] 节点间调度完成后自动生成路线
- [ ] 前端 SVG 正确绘制节点、包裹点与路线
- [ ] **核心主链路全部打通**：F007 → F021 → F005 → F006 → F010

**对应需求**：F006、F010

### 阶段 7：异常与重规划（F013）

**阶段目标**：记录异常事件，支持手动触发重规划并保留版本关系。

| 后端 | 前端 |
| --- | --- |
| `exception_events` 表与 CRUD API | 异常录入表单（类型、目标、描述） |
| 异常类型：道路 / 包裹 / 节点 | 异常列表页 |
| 推荐动作：redispatch（F007+F005+F006）/ reroute（仅 F006） | 「触发重规划」按钮 |
| 重规划写入新版本（parent_id、version、replan_reason、is_replan） | 原方案 vs 新方案标识 |
| `POST /api/exceptions`、`/{event_code}/replan` | 重规划后刷新工作台与路线图 |

**阶段产出**：

- [ ] 可创建并查看异常事件
- [ ] 重规划后生成新版本方案，原方案保留可查看
- [ ] 节点异常触发重调度、道路异常触发重规划路径

**对应需求**：F013（F012 异常模拟 UI 可简化，复用异常录入表单）

### 阶段 8：AI 助手与收尾

**阶段目标**：接入 DeepSeek 自然语言调度，完成埋点与验收打磨。

| 后端 | 前端 |
| --- | --- |
| `deepseek_service.py` 封装 | AI 助手对话框 |
| `POST /api/ai/parse`：自然语言 → 参数 → 自动调度 | 发送消息、展示调度结果 |
| 降级策略：失败时 `meta.degraded=true` + 默认算法参数 | 降级提示（不伪装 AI 成功） |
| `log_events` 埋点（login、schedule、replan 等） | 管理者只读权限全面检查 |
| P1 占位接口返回 501（explain / review / compare） | P1 菜单项置灰或「即将推出」 |
| OpenAPI 文档整理、Bug 修复 | 全局错误提示、loading、空状态优化 |
| 演示数据与主链路回归测试 | 答辩演示路径打磨 |

**阶段产出**：

- [ ] F014 自然语言可触发调度（DeepSeek 不可用时可降级）
- [ ] 关键操作有埋点记录
- [ ] MVP 整体可演示、可验收

**对应需求**：F014、3.2 埋点

| --- | --- |

## 6. 风险与应对

| 风险 | 应对策略 |
| --- | --- |
| 算法调不通或超时 | 先保证有结果且满足硬约束；设迭代上限；不追求最优解 |
| 前后端阻塞等待 | 每阶段先定 API 契约；前端用 Mock 并行 |
| 状态流转逻辑复杂 | 阶段 6 专门验证；编写状态流转对照表 |
| DeepSeek 课堂不可用 | 传统算法按钮必须可用；降级提示必须可见 |
| 范围膨胀 | 严格按本文档阶段推进；新需求记入 P1  backlog |
