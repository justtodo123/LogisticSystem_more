### 前端适配说明（非阻塞）

| 差异 | 处理 |
|------|------|
| 契约 `coordinates` 返回 `{ vehicle_code, routes[] }` 嵌套结构，架构 §6.5.4 为扁平 `nodes/packages/segments` | 新增 [`route-normalize.ts`](../src/frontend/src/utils/route-normalize.ts)；`nodes`/`packages` 从 `dispatch.tasks` 推导，`segments` 来自 `route_segments` |
| `coordinates` 接口无 `total_time`、无节点/包裹 | 通过 `GET /routes/{route_code}` 取 `total_time` 与路段 |
| 联调调用链 | 真实 API：`GET /routes?vehicle_code&batch_code` → `GET /routes/{route_code}`（规避路由顺序风险，见 P1） |
| F006 触发方式 | 由 Dashboard「路径规划」按钮调用 `POST /api/routes/plan`；未规划时路线列表为空 |

### P0 状态

### P1 建议（可选）

| 项 | 说明 |
|----|------|
| F005 完成后自动触发 F006 | 契约 §7.2 写明自动规划，但 `dispatch_service` 未调用 `RouteService`；前端已用 Dashboard 按钮补齐，联调不依赖 Swagger |
| `GET /by-vehicle/.../coordinates` 路由注册顺序 | `/{route_code}` 注册在 `/by-vehicle/...` 之前，部分环境下可能将 `by-vehicle` 误匹配为 `route_code`；建议将 `/by-vehicle/{vehicle_code}/coordinates` 移到 `/{route_code}` 之前 |
| 架构 §6.5.4 与 `api-contract-phase5.md` 字段不一致 | 建议统一文档，或以契约为准更新架构说明书 |
