## 2. PRD V2.7更新记录

### 2.1 更新位置

- 更新位置：§1.2 背景假设与物流模型 → 新增 §1.2.3 接口设计决策
- 更新时间：2026年6月12日

### 2.2 更新内容

新增"1.2.3 接口设计决策"小节，包含以下3个接口设计决策：

#### 决策1：订单创建接口设计（对应F001）

- **决策**：创建订单时同时创建货物，`OrderCreate` Schema包含`goods`列表（`List[GoodsCreate]`）
- **理由**：简化前端操作，一次API调用完成订单和货物的创建，符合用户"录入订单信息"的自然流程
- **影响范围**：`POST /api/orders`接口的请求体格式、后端服务层实现

#### 决策2：包裹重新打包接口设计（对应F001-2）

- **决策**：重新打包接口（`POST /api/packages/{package_code}/repack`）的输入只包含`goods_codes`列表，不需要指定目标节点或重新计算重量体积
- **理由**：repack是在同一订单内重新分配货物到包裹，目标节点不变（仍是原订单的`destination_node`），重量体积由系统自动重新计算
- **影响范围**：`POST /api/packages/{package_code}/repack`接口的请求体格式、后端服务层实现

#### 决策3：订单批量导入接口设计（对应F001）

- **决策**：批量导入接口（`POST /api/orders/import`）的`skip_errors`参数默认值为`True`，即默认跳过错误行，返回部分成功结果
- **理由**：符合PRD中"部分成功（跳过错误行）"的描述，提高导入效率，用户体验更好
- **影响范围**：`POST /api/orders/import`接口的默认行为、前端调用方式

## 6. 附录：假设详细分析

### 6.1 假设1详细分析

**原始假设**：OrderCreate Schema包含goods列表，创建订单时同时创建货物

**问题分析**：
- PRD V2.7 F001订单管理的用户故事说的是"录入订单信息"，F001-1货物管理说的是"录入货物信息"，暗示订单和货物是分开管理的
- 架构设计说明书§6.5.2只定义了`POST /orders`接口，但没有定义请求体格式
- 假设创建订单时需要同时创建货物，但这个假设与PRD中订单和货物分开管理的意图可能不一致

**澄清结果**：确认为"创建订单时同时创建货物"，已更新到PRD V2.7 §1.2.3

### 6.2 假设2详细分析

**原始假设**：PackageRepack Schema只包含goods_codes

**问题分析**：
- PRD V2.7 F001-2说"手动重新打包包裹"，但没有定义repack接口的输入格式
- 架构设计说明书§6.5.2定义了`POST /packages/{package_code}/repack`接口，但没有定义请求体
- 假设repack只需要货物编号列表，但repack的完整语义可能更复杂（是否需要指定目标节点？是否需要重新计算重量？）

**澄清结果**：确认为"repack只需要goods_codes列表"，已更新到PRD V2.7 §1.2.3

### 6.3 假设3详细分析

**原始假设**：所有模型都配置了SQLAlchemy relationship

**问题分析**：
- 架构设计说明书§5只提供了DDL，没有定义ORM模型间的relationship配置
- PRD V2.7 §3.6只定义了表字段，没有定义relationship
- 假设所有外键都需要配置relationship，但这会影响查询性能和懒加载策略

**澄清结果**：确认为"所有外键都配置SQLAlchemy relationship"，已更新到架构设计说明书 §2 Q13

### 6.4 假设4详细分析

**原始假设**：服务层方法都是staticmethod，返回Pydantic Schema

**问题分析**：
- 架构设计说明书和PRD V2.7都没有定义服务层的方法签名
- 假设了方法都是`@staticmethod`，但实际是否应该是实例方法？
- 假设了返回Pydantic Schema，但实际应该返回什么类型？

**澄清结果**：确认为"服务层方法采用@staticmethod静态方法，返回Pydantic Schema"，已更新到架构设计说明书 §2 Q14

### 6.5 假设5详细分析

**原始假设**：订单批量导入接口skip_errors参数默认值为True

**问题分析**：
- 架构设计说明书§6.5.2只定义了接口路径和HTTP方法，没有定义参数默认值
- 假设了`skip_errors`参数有默认值`True`，但PRD和用户澄清中都说是"部分成功（跳过错误行）"，这意味着默认应该跳过错误

**澄清结果**：确认为"skip_errors默认值为True"，已更新到PRD V2.7 §1.2.3

### 6.6 假设6详细分析

**原始假设**：演示数据初始化按特定顺序执行

**问题分析**：
- PRD V2.7 §3.4只说了要初始化哪些数据，没有说初始化顺序
- 架构设计说明书§5.7也说要初始化演示数据，但没有说顺序
- 假设的初始化顺序可能影响数据依赖性（例如，创建订单前必须先创建货物吗？）

**澄清结果**：确认为"按用户→节点→车辆→司机→货物→订单顺序初始化"，已更新到架构设计说明书 §2 Q15
