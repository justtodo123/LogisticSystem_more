# 08 — 优化点说明

> 最后更新：2026-08-19 | 面向：了解优化改进全貌 + 已知边界

## 优化总览

项目原为 MVP 阶段完成、P1 功能交付的状态。通过 **23 个优化任务**（T0-1 ~ T6-2）在以下 7 个方面进行了全面加固。

---

## 阶段 0：地基 — 生产必备基础设施（5 任务）

| 任务 | 内容 | 价值 |
|------|------|------|
| **T0-1** 分环境配置 | dev/staging/prod 三环境 `.env.*`，pydantic-settings 集中管理，密钥入口加 `JWT_SECRET` | 消除硬编码密钥，支持 CI 多环境注入 |
| **T0-2** 细粒度 RBAC | 扩展 4 角色（admin/dispatcher/operator/viewer），`require_permission`/`require_role` 工厂函数 | 调度操作受角色保护，权限体系可扩展 |
| **T0-3** 操作审计日志 | `middleware/audit_log.py` 记录操作事件 + IP + User-Agent | 可追溯操作历史 |
| **T0-4** 幂等控制 | `Idempotency-Key` 请求头去重（24h TTL），含输入校验增强 `core/validators.py` | 防止重复提交、网络重试副作用 |
| **T0-5** 服务降级与异常兜底 | 全局请求超时 30s + fallback 降级策略 + DeepSeek 超时 15s | 单点故障不拖垮整个服务 |

## 阶段 1：模型 — 业务模型完整性（4 任务）

| 任务 | 内容 | 价值 |
|------|------|------|
| **T1-1** 订单状态扩展 | 从 4 状态扩展到 6 状态（unassigned/assigned/in_transit/signed/exception/closed） | 覆盖真实物流全生命周期 |
| **T1-2** 运力模型增强 | Vehicle 新增 plate_number/time_window/route_limit/cost_per_km/load_rate_max；Driver 新增 shift/工时限制 | 支持时段约束、成本核算、排班管理 |
| **T1-3** 节点类型扩展 | 从 2 种扩展到 5 种（仓储/分拣/区域中心/分部/合作点） | 支持多级物流网络 |
| **T1-4** 状态机同步 | 更新 `ORDER_TRANSITIONS`，所有状态变更走单一入口 | 状态一致性保证 |

## 阶段 2：调度引擎 — 可插拔化 + 多目标优化（4 任务）

| 任务 | 内容 | 价值 |
|------|------|------|
| **T2-1** 策略模式重构 | `base.py` ABC + `factory.py` + 3 个策略实现，引擎从 `algorithm_config.json` 读取 | 算法可插拔，调试可用 DummyStrategy |
| **T2-2** 多目标评分引擎 | 5 目标归一化加权排序，Top-K 候选（≥3），响应含 score_breakdown/composite_score | 不只给出"一个方案"，还有备选和评分拆解 |
| **T2-3** 可解释性 | `algorithms/explainer.py` 生成评分拆解+约束命中+备选理由，落库 `explanation_data` 列 | 调度员理解"为什么选这个方案" |
| **T2-4** 人工干预 | 4 端点：换车/换司机/重算/撤销，含校验+版本链+前端 VehicleTaskTable 交互 | 调度员可纠正算法不可见的实际情况 |

## 阶段 3：异常 + 通知 — 闭环处理（2 任务）

| 任务 | 内容 | 价值 |
|------|------|------|
| **T3-1** 异常重规划增强 | partial/full/hybrid 三策略 + 差异报告 + 去重 | 精准重调度，影响范围可控 |
| **T3-2** 消息通知服务 | 可插拔渠道（Console/Email/企业微信），4 场景挂载（调度确认/异常/重规划/送达），运行时配置切换 | 关键事件主动通知，不依赖人工巡检 |

## 阶段 4：工程化 — 性能 + 可靠性（3 任务）

| 任务 | 内容 | 价值 |
|------|------|------|
| **T4-1** CI/CD | GitHub Actions ci.yml（pytest + vue-tsc build）+ cd.yml（GHCR 双镜像推送） | 每次提交自动验证，main 自动构建镜像 |
| **T4-2** 数据库索引 | 7 个高频查询索引（orders/ goods/ packages/ node_dispatches） | 1000 行分页从 ~200ms 降到 ~10ms |
| **T4-3** Redis 缓存层 | `@cached` 装饰器 + 读写失效 + Redis 失败自动降级内存 | 列表热点缓存，写操作主动失效 |

## 阶段 5：外部对接 — 生态系统集成（3 任务）

| 任务 | 内容 | 价值 |
|------|------|------|
| **T5-1** ERP/WMS 导入导出 | CSV(xlsx) 导出（带 BOM）+ Excel 导入（列映射/skip_errors）+ ERP webhook（API Key/JWT 双鉴权） | 对接企业现有系统 |
| **T5-2** 地图服务集成 | 三档距离降级（路网 API → 直线×系数 → Haversine）+ 高德地图真实路径渲染 + 无 Key 降级 Canvas 折线 | 开发/演示无阻塞，生产有 Key 自动升级精度 |
| **T5-3** 报表分析模块 | 4 类报表（SLA/成本/异常/运力）+ Dashboard 前端（KPI 卡片 + 图表） | 管理层可视化决策 |

## 阶段 6：AI 加固 — 可靠性 + 可控性（2 任务）

| 任务 | 内容 | 价值 |
|------|------|------|
| **T6-1** AI 输出结构化校验 | Pydantic Schema 校验 + 错误反馈重试（最多 3 次）+ 业务规则闸门（权重和≈1） | AI 输出不可控→可控，错误不静默通过 |
| **T6-2** AI 建议确认闸门 | `AiSuggestion` 模型（info/suggestion/action 三级）+ 确认/拒绝端点 + 前端按钮 | AI 只建议不执行，人工确认后生效 |
