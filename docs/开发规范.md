## 依赖管理

- **后端**：`pip install -r requirements.txt`，依赖版本为下限约束（`>=`）。不要手动编辑锁文件，没有 lock 文件。
- **前端**：`npm install`，依赖版本为 `^` 兼容约束。不要手动编辑 `package-lock.json`。
- **新增依赖**：在 `requirements.txt` / `package.json` 中添加，团队 review 后合入。

## 代码风格

### 后端（Python）

- 遵循 PEP 8，4 空格缩进
- 异步端点使用 `async def`；同步计算或同步 SQLAlchemy 服务保持同步，调用方必须遵守函数的同步/异步契约
- 服务层函数可同步或异步，不得假设 `services/` 全部为 `async def`
- 日志使用 `logging.getLogger(__name__)`
- 响应使用统一格式：`utils/response.py` 的 `success_response()` / `error_response()`
- 错误码使用 `core/error_codes.py` 中预定义常量

### 前端（TypeScript）

- 使用 `<script setup lang="ts">` 语法
- 组件按功能分目录：`components/crud/`/`detail/`/`schedule/`/`ai/`/`charts/`
- API 调用统一经 `api/request.ts` 封装的 axios 实例
- 组合式逻辑抽到 `composables/`（命名 `use*`）
- 类型定义放在 `types/`，按领域拆分

## API 响应格式

```json
// 业务成功
{ "code": 0, "message": "success", "data": { ... }, "meta": { ... } }

// 业务错误
{ "code": 40000, "message": "参数校验失败", "data": null, "meta": {} }
```

- 对外唯一响应 envelope 为 `code/message/data/meta`；错误时 `data` 固定为 `null`。
- HTTPException.detail 仅作为内部兼容输入，由全局 handler 转换；不要把 `{ "detail": "Not Found" }` 当作当前外部契约。

- 分页列表统一格式：`data: { items: [...], total: N, page: P, page_size: S }`
- 降级信息通过 `meta.degraded` + `meta.degraded_reason` 传递

## 错误码体系

| 范围 | 含义 |
|------|------|
| `0` | 成功 |
| `40000-40021` | 参数/历史业务错误 |
| `40100-40101` | 未登录 / Token 过期 |
| `40300-40301` | 权限不足 / 审计拒绝 |
| `40400` | 通用资源不存在 |
| `40900-40905` | 冲突、幂等和业务编号分配 |
| `41300` | 请求体过大 |
| `42900` | 登录限流 |
| `50000-50001` | 内部错误 / 数据库不可用 |
| `50400` | 请求超时 |

降级成功仍使用 `code=0`，通过 `meta.degraded` / `meta.degraded_reason` 表示；当前 registry 不再为 AI/外部服务降级保留独立的 `600xx` 成功错误码范围。

错误码常量定义在 `core/error_codes.py`，避免各处硬编码。

## 目录约定

- `src/backend/api/` — 路由层（不写业务逻辑）
- `src/backend/services/` — 业务逻辑（不直接操作 HTTP）
- `src/backend/models/` — SQLAlchemy ORM 模型
- `src/backend/schemas/` — Pydantic 请求/响应 Schema
- `src/backend/algorithms/` — 调度算法（含策略模式基类+工厂+评分+可解释性）
- `src/backend/core/` — 公共基础设施（权限/错误码/校验器/AI 守卫/降级）
- `src/backend/middleware/` — FastAPI 中间件（审计/幂等/超时）
- `src/frontend/src/views/` — 页面组件
- `src/frontend/src/components/` — 可复用组件
- `src/frontend/src/composables/` — Vue 组合式函数
- `src/frontend/src/api/` — 后端 API 调用封装

## 数据库迁移

- 使用 Alembic，迁移文件在 `src/backend/alembic/versions/`
- 新增模型/字段后：`alembic revision --autogenerate -m "描述"` → review 生成的迁移脚本 → `alembic upgrade head`
- Alembic 是正式 schema 的唯一迁移入口；发布/首次启动前显式执行 `python -m alembic -c alembic.ini upgrade head`
- FastAPI startup、Uvicorn worker 和业务请求禁止执行建表、ALTER 或 CREATE INDEX
- `Base.metadata.create_all()` / `config.database.init_db()` 仅供隔离测试，不得用于部署迁移
- 旧 SQLite 升级前必须备份；未知 revision、多版本行或未知 schema fail closed，禁止用 `stamp head` 掩盖差异

## 环境变量使用

- 后端：所有配置通过 `config/settings.py` 的 `Settings` 类集中管理，禁止代码中直接 `os.getenv`
- 前端：`VITE_*` 前缀变量通过 `import.meta.env.VITE_*` 访问，`.env.local` 不提交 Git
