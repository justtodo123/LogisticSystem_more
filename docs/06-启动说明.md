## 前置条件

| 工具 | 最低版本 | 检查命令 |
|------|---------|----------|
| Python | 3.11+（项目 CI/runtime 基线为 3.13） | `python --version` |

## 方式一：本地开发启动（推荐联调）

### 1) 后端

```bash
cd src/backend

# 复制环境配置模板
cp .env.example .env.dev
# 编辑 .env.dev，至少修改 JWT_SECRET（随机字符串即可）
# 可选：填写 DEEPSEEK_API_KEY 以启用 AI 功能

# 安装依赖
pip install -r requirements.txt

# 显式迁移 schema（应用启动和 worker 不执行 DDL）
python -m alembic -c alembic.ini upgrade head

# 初始化完整演示数据（同时创建 admin / dispatcher / manager）
python scripts/init_demo_data.py

# 如果只需要创建上述种子账号、不生成演示业务数据，改为单独运行：
# python scripts/init_users.py

# 启动后端（默认 http://localhost:8000）
uvicorn main:app --reload --port 8000
```

> **数据安全提示**：`init_demo_data.py` 会先清理当前数据库中的订单、货物、车辆、司机、节点、调度、路线、事件及相关演示账号，再重建完整 Demo 数据。仅可对可丢弃的非生产演示数据库执行；运行前务必核对 `.env.dev` 中的 `DATABASE_URL`，不要用于生产库或任何需要保留数据的开发库。固定密码 `123456` 也只用于非生产演示。

访问 [http://localhost:8000/docs](http://localhost:8000/docs) 查看 Swagger API 文档。

> Alembic 是正式 schema 的唯一迁移入口。升级旧 SQLite 前先备份；未知 revision、多行 `alembic_version` 或未知结构必须停止并人工处理，禁止直接 `stamp head`。`Base.metadata.create_all()` 仅允许隔离测试使用。

### 2) 前端

```bash
cd src/frontend

# 复制环境配置模板
cp .env.example .env.local
# 默认全部 VITE_USE_MOCK_*=true，可直接运行（不依赖后端）

npm install
npm run dev  # 默认 http://localhost:5173
```

### 3) 联调

前端默认全部走 Mock。逐步关闭 Mock 开关以联调后端：

1. 编辑 `.env.local`，将 `VITE_USE_MOCK_AUTH=false`
2. 重启前端，确认能用已初始化的后端账号（推荐 `admin / 123456`）登录
3. 依次关闭其他 `VITE_USE_MOCK_*` 开关
4. 每次关闭一个后重启前端，在对应页面验证

详细步骤见[前后端联调规范](前后端联调规范.md)。

### 4) 运行测试

```bash
# 后端全部测试
cd src/backend
python -m pytest -q

# 前端类型检查 + 构建
cd src/frontend
npx vue-tsc --noEmit
npm run build
```

### 5) 本地无容器 smoke（02A）

在全新临时 SQLite 上验证种子库主链路，不改开发库，不需要 Docker：

```powershell
src\backend\.venv\Scripts\python.exe src\backend\scripts\smoke_local.py --self-host --port 18000 --temp-dir tmp\logistics-02a
```

已有后端进程时，只打 HTTP：

```powershell
src\backend\.venv\Scripts\python.exe src\backend\scripts\smoke_local.py --base-url http://127.0.0.1:8000
```

## 可观测性（R2-06）

后端默认输出一行一条的 JSON 日志，字段包括 `request_id` / `trace_id` / `task_id`（如有）以及脱敏后的用户与幂等键。调用方可传入 `X-Request-ID`、`X-Trace-ID`、`X-Task-ID`；缺省时由服务生成并在响应头回写。

- 健康检查：`GET /api/health`
- 核心指标：`GET /metrics`（JSON）或 `GET /metrics?format=prometheus`
- 日志级别：环境变量 `LOG_LEVEL`（默认 `INFO`）
- 失败请求可按 `request_id` 对照日志与 SQL 注释（`/* request_id=... */`）排查
- 压测脚本：`load/k6/load.js`、`load/k6/spike.js`；完整 load/spike 走 GitHub Actions workflow `P1 load and spike`，不在本机 Docker 上执行

## 方式二：Docker 一键启动（无需安装 Python/Node）

> 2026-09-04：以下命令为配置说明。本机未执行 Docker Compose 业务验收；第一轮 02B 仍为 `mitigated`，已转入 [R2 后续事项](../My_doc/plan_todo/post-r2-followups.md)，不属于 R2 工程交付阻断项。第一轮原始记录见 [plan 02](../My_doc/post_plan/第一轮优化计划/02-docker-seed-e2e.md)。

```bash
# 根目录；一次性 migrate 成功后 backend 才启动
docker compose up -d

# backend 就绪后初始化数据
docker exec -it logistics-backend python scripts/init_demo_data.py
```

访问 [http://localhost:8080](http://localhost:8080)。

> **注意**：Compose 会先由一次性 `migrate` 服务运行 `scripts/release_migrate.py`。它只创建 fresh SQLite，或验证已处于当前 Alembic head 且无 metadata drift 的现有库；旧版、漂移或未知库会阻止 backend 启动，且不会被原地修改。旧 SQLite 必须先用 `scripts/migrate_sqlite.py` 分类并复制升级。该门禁不会自动初始化 Demo 数据。
>
> 容器内的 `init_demo_data.py` 同样会清理目标数据库后重建完整 Demo 数据。只可对可丢弃的非生产 Demo 数据卷执行，运行前先确认 Compose 注入的 `DATABASE_URL` 和挂载数据卷；生产库或需保留数据的卷不得执行。

## 方式三：仅前端（Mock 演示）

无需启动后端，前端 Mock 模式可独立运行所有功能演示：

```bash
cd src/frontend
cp .env.example .env.local  # 确认所有 VITE_USE_MOCK_*=true
npm install
npm run dev
```

访问 [http://localhost:5173](http://localhost:5173)，使用预定义 Mock 账号（推荐 `admin`）和密码 `123456` 登录。Mock 模式不请求后端 JWT，但用户名仍须存在于下方 Mock 账号表中。

## 演示账号

### 真实后端种子账号

运行 `python scripts/init_users.py` 或 `python scripts/init_demo_data.py` 后可用：

| 角色 | 用户名 | 密码 | 权限说明 |
|------|--------|------|----------|
| 管理员 | `admin` | `123456` | 全部权限，包括用户管理 |
| 调度员 | `dispatcher` | `123456` | 除用户管理外的业务权限 |
| 物流管理者 | `manager` | `123456` | 兼容角色，当前权限与 `warehouse_operator` 相同 |

### 仅前端 Mock 账号

`VITE_USE_MOCK_AUTH=true` 时，前端接受以下预定义用户名，密码均为 `123456`：

- `admin`
- `dispatcher`
- `manager`
- `viewer`
- `warehouse_operator`

Mock 账号用于展示前端路由和按钮权限，不代表后端数据库中已经存在同名用户；真正的授权边界仍是后端权限依赖。

## 后端环境变量快速参考

| 关键变量 | 默认值 | 说明 |
|----------|--------|------|
| `JWT_SECRET` | 默认（**必须改**） | JWT 签名密钥 |
| `DEEPSEEK_API_KEY` | 空 | 空时 AI 自动降级 |
| `MAP_PROVIDER` / `MAP_API_KEY` | 空 | 空时后端路线计算降级；如启用真实路网需同时配置 provider 和 key |
| `REDIS_ENABLED` | `false` | Redis 开关 |
| `DATABASE_URL` | `sqlite:///./data/logistics.db` | runtime/Alembic 共用；修改后先显式迁移 |

完整变量表见[环境配置说明](环境配置说明.md)。

## 常见问题

| 问题 | 解决 |
|------|------|
| `pip install` 失败 | 确认 Python 版本 ≥ 3.11 |
| 后端启动后 `ModuleNotFoundError` | 确认在 `src/backend` 目录下运行 |
| 前端白屏 / API 404 | 检查 Vite 代理配置：`vite.config.ts` 的 proxy 指向 `http://localhost:8000` |
| AI 功能全部降级 | `DEEPSEEK_API_KEY` 为空，填写后重启 |
| 地图只显示折线 | `VITE_MAP_API_KEY` / `MAP_API_KEY` 为空，填写后重启 |
| 登录失败 | 确认已执行 `init_users.py` 或 `init_demo_data.py`、数据库迁移已完成，且登录所用数据库与初始化脚本一致 |
| Docker 启动后数据库为空 | 确认目标是可丢弃的非生产 Demo 数据卷后，再进入容器执行 `python scripts/init_demo_data.py`；该命令会清理并重建数据 |
