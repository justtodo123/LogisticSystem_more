- 数据库：SQLite（生产不可用，需迁移到 MySQL）
- 缺少 Docker 容器化
- 无 CI/CD 流水线
- 无环境分离（dev/staging/prod）
- 前端缺少调度工作台可视化
- 调度算法的 N+1 查询性能问题
- 缺少消息通知（短信/邮件/企业微信）
- 缺少对外系统对接接口（ERP/WMS/TMS）
- 无 API 限流、无日志采集、无监控告警wr

### Phase B：业务模型完善

#### B1 订单状态机补全（2天）

**当前状态**：`pending → delivering → completed`（3 个状态）
**目标状态**：`待分配 → 已分配 → 运输中 → 已签收 → 异常 → 关闭`（6 个状态）

**任务**：
1. [ ] `models/order.py` — 新增 `status` 字段枚举值：`unassigned`, `assigned`, `in_transit`, `signed`, `exception`, `closed`
2. [ ] `services/state_machine.py` — 新增订单状态流转规则：
   - F007 完成：`unassigned` → `assigned`
   - F005 完成：`assigned` → `in_transit`
   - 全部货物送达：`in_transit` → `signed`
   - 异常触发：任一状态 → `exception`
   - 异常关闭：`exception` → `closed`（需有权限判断）
3. [ ] 新增订单状态流转校验：禁止非法跳转（如 `signed` → `delivering`）
4. [ ] Alembic 迁移：更新 Order 模型 + 历史数据兼容
5. [ ] 更新 `order_service.py` 中所有状态相关判断
6. [ ] 前端 `OrderList.vue` 状态筛选器和徽标更新
