## 2. 功能范围

### 2.1 F007全局调度算法

**功能描述**：为每票货物规划L0→L1→L2路径，考虑硬约束，使用贪心算法选择评分最低的1级分拣中心。

**输入**：
- `order_codes`：订单列表（可选，不传则处理所有status=pending的订单）
- `algorithm`：算法类型（traditional/deepseek，阶段3只实现traditional）

**输出**：
- `GlobalSchedule`对象：包含schedule_code、total_distance、total_time、total_goods、score、goods_schedules（JSON）

**算法流程**：
1. 根据订单的0级分拣中心ID，确定每个订单的目的地（L2节点）
2. 根据货物的存储中心ID，确定每个货物的起点（L0节点）
3. 遍历所有L1节点（1级分拣中心）：
   a. **检查硬约束**：容量限制、同订单汇聚、最大存储时长
   b. **计算评分**：score = w1×distance(L0→L1) + w2×time(L0→L1) + w3×1（包裹数）
   c. **贪心选择**：选择评分最低的L1节点
4. 生成每个货物的运输路径（L0→L1→L2）
5. 计算总距离、总时间、货物数量、包裹数量

**硬约束**：
- 一级分拣中心容量限制：该L1节点下`status=packed`的包裹数量 + 1 > l1.capacity → 跳过（包裹数量上限，capacity来自`sorting_centers`表）
- 同订单汇聚：同一订单的所有货物必须经过同一个L1中心（运行时记录`order_l1_map`）
- 最大存储时长：goods.volume × 预估在L1存储时间 > l1.max_storage_time → 跳过（max_storage_time来自`sorting_centers`表，单位：小时）

**配置项**（`algorithm_config.json`，完整示例）：
```json
{
  "global_schedule_weights": {
    "w1_distance": 0.5,
    "w2_time": 0.3,
    "w3_packages": 0.2
  },
  "node_dispatch_weights": {
    "w1_distance": 0.5,
    "w2_time": 0.3,
    "w3_packages": 0.2
  },
  "route_planning_weights": {
    "w1_distance": 0.4,
    "w2_time": 0.4,
    "w3_emission": 0.2
  }
}
```

> **注意**：阶段3仅使用 `global_schedule_weights`，其他配置项为阶段4-5预留。硬约束数值（L1容量上限、最大存储时长）是`sorting_centers`表的字段，不是`algorithm_config.json`的配置项。算法直接从数据库读取L1节点属性进行约束检查。

### 2.2 F021打包算法

**功能描述**：L0→L1按节点对打包，L1→L2按订单打包。

**输入**：
- `goods_schedules`：F007输出的货物调度计划（List[Dict]）
- `schedule_id`：全局调度方案ID（用于生成package_code）

**输出**：
- `Package`对象列表：包含package_code、weight、volume、status、from_node_id、to_node_id、goods_items（JSON）

**打包规则**：
- L0→L1：按from_node_id + to_node_id分组，同一组的货物打包成一个包裹
- L1→L2：按order_id分组，同一订单的货物打包成一个包裹

**包裹状态**：
- 初始状态：pending_pack
- 打包完成：packed

## 5. 算法设计

### 5.1 F007全局调度算法

**文件**：`src/backend/algorithms/global_schedule.py`

**类/函数**：
- `global_schedule(order_codes: List[str], algorithm: str, db: Session) -> Dict`

**算法步骤**：
1. 查询订单列表（如果order_codes为空，则查询所有status=pending的订单）
2. 遍历每个订单的每个货物：
   a. 获取货物起点（L0节点）：goods.node_id（存储中心）
   b. 获取订单目的地（L2节点）：order.destination_node_id（0级分拣中心）
   c. 遍历所有L1节点（1级分拣中心）：
      - **检查硬约束1**：L1容量是否足够（该L1节点下status=packed包裹数 + 1 > l1.capacity，包裹数量上限）→ 不满足则跳过
      - **检查硬约束2**：同订单汇聚（如果订单已有其他货物被分配L1，则必须走同一个L1）→ 不满足则跳过
      - **检查硬约束3**：最大存储时长（goods.volume × 预估在L1存储时间 > l1.max_storage_time）→ 不满足则跳过
      - **计算评分**：score = w1×distance(L0→L1) + w2×time(L0→L1) + w3×1（包裹数）
      - **贪心选择**：记录评分最低的L1节点
   d. 为当前货物选择评分最低的L1节点，生成路径：[L0_code, L1_code, L2_code]
3. 计算总距离、总时间、货物数量、包裹数量
4. 返回结果

**关键代码逻辑**：
```python
# 伪代码
def global_schedule(order_codes, algorithm, db):
    # 1. 查询订单
    orders = db.query(Order).filter(Order.order_code.in_(order_codes)).all() if order_codes else db.query(Order).filter(Order.status == "pending").all()

    # 预加载L1节点列表（含capacity、max_storage_time字段）
    l1_nodes = db.query(Node).filter(Node.node_type == "sorting_center", Node.level == 1).all()

    # 2. 遍历订单和货物
    goods_schedules = []
    order_l1_map = {}  # 记录每个订单已分配的L1节点，用于硬约束2（同订单汇聚）

    for order in orders:
        for goods in order.goods:
            # 2a. 获取L0节点（起点）
            l0_node = db.query(Node).filter(Node.id == goods.node_id).first()

            # 2b. 获取L2节点（目的地）
            l2_node = db.query(Node).filter(Node.id == order.destination_node_id).first()

            # 2c. 遍历L1节点，选择最优（贪心：评分最低）
            best_l1 = None
            best_score = float('inf')
            for l1_node in l1_nodes:
                # ---- 硬约束检查 ----
                # 硬约束1：L1容量（包裹数量上限，统计该L1节点下status=packed的包裹数）
                packed_count = db.query(Package).filter(
                    Package.to_node_id == l1_node.id,  # 正确：统计到达L1的包裹
                    Package.status == "packed"
                ).count()
                if packed_count + 1 > l1_node.capacity:
                    continue
                # 硬约束2：同订单汇聚（订单已有货物分配了L1，必须走同一个L1）
                if order.order_code in order_l1_map and order_l1_map[order.order_code] != l1_node.node_code:
                    continue
                # 硬约束3：最大存储时长（goods.volume × 预估在L1存储时间 > l1.max_storage_time）
                estimated_storage_hours = calculate_storage_time(l0_node, l1_node, l2_node)  # 伪代码
                if goods.volume * estimated_storage_hours > l1_node.max_storage_time:
                    continue

                # 计算评分：score = w1×dist(L0→L1) + w2×time(L0→L1) + w3×1
                score = (config["w1_distance"] * haversine(l0_node, l1_node)
                        + config["w2_time"] * estimated_storage_hours
                        + config["w3_packages"] * 1)

                # 贪心选择（评分最低）
                if score < best_score:
                    best_score = score
                    best_l1 = l1_node

            # 2d. 生成路径
            if best_l1:
                path = [l0_node.node_code, best_l1.node_code, l2_node.node_code]
                goods_schedules.append({
                    "goods_code": goods.goods_code,
                    "order_code": order.order_code,
                    "path": path
                })
                # 记录订单→L1映射（用于后续货物的硬约束2检查）
                order_l1_map[order.order_code] = best_l1.node_code
            else:
                # 无满足条件的L1，抛出业务异常
                raise ValueError(f"无法为货物{goods.goods_code}找到满足条件的L1分拣中心")

    # 3. 计算结果
    total_distance = calculate_total_distance(goods_schedules)
    total_time = calculate_total_time(goods_schedules)
    goods_count = len(goods_schedules)
    package_count = calculate_package_count(goods_schedules)

    # 4. 返回
    return {
        "schedule_code": generate_schedule_code(),
        "order_codes": [o.order_code for o in orders],
        "total_distance": total_distance,
        "total_time": total_time,
        "total_goods": goods_count,
        "score": best_score,  # 注：实际应累计所有货物的评分
        "goods_schedules": goods_schedules
    }
```

### 5.2 F021打包算法

**文件**：`src/backend/algorithms/packaging.py`

**类/函数**：
- `packaging(schedule_result: Dict, schedule_id: int, db: Session) -> List[Package]`

**算法步骤**：
1. 从F007输出结果中获取goods_schedules
2. **L0→L1打包**：遍历goods_schedules，按(path[0], path[1])即(L0_code, L1_code)节点对分组，同一组的货物打包成一个包裹
3. **L1→L2打包**：遍历goods_schedules，按order_code分组，同一订单的货物打包成一个包裹（同一订单所有货物的path[2]即L2_code相同）
4. 创建Package对象，设置status=pending_pack
5. 返回Package列表

**关键代码逻辑**：
```python
# 伪代码
def packaging(schedule_result, schedule_id, db):
    # 1. 获取goods_schedules
    goods_schedules = schedule_result["goods_schedules"]
    packages = []

    # 2. L0→L1打包：按(L0_code, L1_code)节点对分组
    from collections import defaultdict
    l0_l1_groups = defaultdict(list)
    for gs in goods_schedules:
        # path = [L0_code, L1_code, L2_code]
        key = (gs["path"][0], gs["path"][1])  # (L0_code, L1_code)
        l0_l1_groups[key].append(gs)

    for (from_code, to_code), gs_list in l0_l1_groups.items():
        # 创建L0→L1包裹
        package = Package(
            package_code=generate_package_code(),
            weight=sum(db.query(Goods).filter(Goods.goods_code == gs["goods_code"]).first().weight for gs in gs_list),
            volume=sum(db.query(Goods).filter(Goods.goods_code == gs["goods_code"]).first().volume for gs in gs_list),
            status="pending_pack",
            from_node_id=db.query(Node).filter(Node.node_code == from_code).first().id,
            to_node_id=db.query(Node).filter(Node.node_code == to_code).first().id,
            goods_items=[{"goods_code": gs["goods_code"], "order_code": gs["order_code"]} for gs in gs_list],
            schedule_id=schedule_id
        )
        packages.append(package)

    # 3. L1→L2打包：按order_code分组（同一订单货物必须打成一个包裹）
    l1_l2_groups = defaultdict(list)
    for gs in goods_schedules:
        key = gs["order_code"]
        l1_l2_groups[key].append(gs)

    for order_code, gs_list in l1_l2_groups.items():
        # 创建L1→L2包裹（from=L1, to=L2）
        l1_code = gs_list[0]["path"][1]
        l2_code = gs_list[0]["path"][2]
        package = Package(
            package_code=generate_package_code(),
            weight=sum(db.query(Goods).filter(Goods.goods_code == gs["goods_code"]).first().weight for gs in gs_list),
            volume=sum(db.query(Goods).filter(Goods.goods_code == gs["goods_code"]).first().volume for gs in gs_list),
            status="pending_pack",
            from_node_id=db.query(Node).filter(Node.node_code == l1_code).first().id,
            to_node_id=db.query(Node).filter(Node.node_code == l2_code).first().id,
            goods_items=[{"goods_code": gs["goods_code"], "order_code": gs["order_code"]} for gs in gs_list],
            schedule_id=schedule_id
        )
        packages.append(package)

    # 4. 返回
    return packages
```

## 6. 服务设计

### 6.1 ScheduleService编排服务

**文件**：`src/backend/services/schedule_service.py`

**类/方法**：
- `ScheduleService`类
- `create_global_schedule(order_codes: List[str], algorithm: str, db: Session) -> Dict`：编排F007→F021→写库（单事务）

**编排流程**（单事务保证原子性，符合架构文档§8.3）：
1. 调用F007算法（global_schedule.py），获取调度结果（纯计算，不写库）
2. 调用F021算法（packaging.py），获取包裹列表（纯计算，不写库）
3. **单事务**：一次性写入global_schedules + packages + 更新orders/goods状态，提交或全回滚
4. 返回结果

**关键代码逻辑**：
```python
# 伪代码
class ScheduleService:
    @staticmethod
    async def create_global_schedule(order_codes, algorithm, db):
        try:
            # 1. 调用F007算法（纯计算，不写库）
            from algorithms.global_schedule import global_schedule
            schedule_result = global_schedule(order_codes, algorithm, db)

            # 2. 调用F021算法（纯计算，不写库）
            from algorithms.packaging import packaging
            packages = packaging(schedule_result, None, db)  # 注意：此处不传schedule_id，F021返回Package对象列表（未写入DB）

            # 3. 单事务：一次性写入global_schedules + packages + 更新orders/goods
            from models.global_schedule import GlobalSchedule
            from models.order import Order
            from models.goods import Goods

            global_schedule_obj = GlobalSchedule(
                schedule_code=schedule_result["schedule_code"],
                order_codes=schedule_result["order_codes"],
                goods_schedules=schedule_result["goods_schedules"],
                total_distance=schedule_result["total_distance"],
                total_time=schedule_result["total_time"],
                total_goods=schedule_result["total_goods"],
                score=schedule_result["score"],
                algorithm_type=algorithm,
                version=1,
                is_replan=False
            )
            db.add(global_schedule_obj)
            db.flush()  # 获取id，供packages关联

            # 写入packages（关联global_schedule_obj.id）
            for pkg in packages:
                pkg.schedule_id = global_schedule_obj.id
                db.add(pkg)

            # 更新orders状态（pending→delivering）
            order_codes_in_schedule = set(gs["order_code"] for gs in schedule_result["goods_schedules"])
            orders = db.query(Order).filter(Order.order_code.in_(order_codes_in_schedule)).all()
            for order in orders:
                order.status = "delivering"

            # 更新goods状态（pending_pack→packed）
            goods_codes_in_schedule = [gs["goods_code"] for gs in schedule_result["goods_schedules"]]
            goods_list = db.query(Goods).filter(Goods.goods_code.in_(goods_codes_in_schedule)).all()
            for goods in goods_list:
                goods.status = "packed"

            db.commit()  # 单事务提交，全部成功或全回滚

            # 4. 返回成功响应
            return {
                "code": 0,
                "message": "success",
                "data": {
                    "schedule_code": schedule_result["schedule_code"],
                    "total_distance": schedule_result["total_distance"],
                    "total_time": schedule_result["total_time"],
                    "total_goods": schedule_result["total_goods"],
                    "score": schedule_result["score"],
                    "package_count": len(packages),
                    "version": 1,
                    "is_replan": False
                }
            }
        except Exception as e:
            db.rollback()  # 单事务回滚，所有写入全部撤销
            return {"code": 40001, "message": f"全局调度失败: {str(e)}", "data": None}
```

## 10. 依赖与风险

### 10.1 依赖

- 阶段0-2已完成：基础数据管理（订单、货物、包裹、节点、车辆、司机）
- 数据库模型：orders, goods, packages, nodes已存在
- 算法配置：algorithm_config.json已存在（需更新）

### 10.2 风险

1. **性能风险**：F007算法遍历所有L1节点，如果L1节点数量多，可能超时（>10秒）
   - 缓解措施：限制L1节点数量，或优化算法（预筛选）
2. **事务超时风险**：单事务写入global_schedules + packages数据量较大，可能事务超时
   - 缓解措施：控制演示数据规模，单批次packages数量不超过100
3. **硬约束数值风险**：L1节点capacity/max_storage_time字段值不合理，导致无法调度
   - 缓解措施：init_demo_data.py中设置合理的默认值
