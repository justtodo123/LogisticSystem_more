## 3. 各功能说明（可选择执行）

### P1-01 · AI 方案解释 / 方案审查

**现状**：`POST /api/ai/explain`、`POST /api/ai/review` 返回 501；前端 `AiAssistantPanel` 已有按钮。

**目标**：

- **方案解释（F015）**：对选定全局/节点间方案，用自然语言说明调度原因。
- **方案审查（F016）**：识别超载、超时等风险，结构化展示。

**执行要点**：

| 端 | 内容 |
| --- | --- |
| 后端 | 替换 501；复用 `deepseek_service`；读 `global_schedules` / `node_dispatches` 组装上下文；支持 `meta.degraded` |
| 前端 | 接真实接口；侧边栏展示解释/风险列表；loading 与降级提示 |

**备注**：项目组标注 **优先级较低**；可与 F014 共用 DeepSeek 配置，实现成本不高。

---

### P1-02 · 前端界面美化

**现状**：MVP 以功能跑通为主，Dashboard、列表页、调度工作台视觉较朴素。

**目标**：整体 UI 更统一、美观，提升答辩演示观感。

**执行要点**（可分期）：

- 统一色彩、间距、卡片与表格样式（Element Plus 主题或自定义 CSS 变量）
- Dashboard / 调度工作台布局优化
- 空状态、加载态、错误提示一致化
- 关键操作按钮层级与反馈（成功/失败 toast）

**备注**：不与业务逻辑强绑定，可与其它项并行；范围需自行划定（全站 vs 核心页）。

---

### P1-03 · 全局调度：条件筛选 + 预览确认

**现状**：全局调度主要依据 **pending 状态订单** 自动生成；生成即落库并改变订单/包裹状态。

**目标**：

1. 用户 **自行选择条件** 参与调度（不限于 pending），例如：多选订单、按目的地/时间/状态筛选。
2. **预览模式**：生成方案但不立即改库；用户 **确认选用** 后才更新订单及包裹信息。

**执行要点**：

| 端 | 内容 |
| --- | --- |
| 后端 | `POST /api/schedule/global` 增加 `order_codes[]` / 筛选参数；增加 `preview=true` 或独立 preview 接口；确认接口 `POST .../confirm` 落库 |
| 前端 | 订单多选 + 筛选 UI；「生成预览」「确认采用」两步流；预览态明确标识 |
| 数据 | 可选：`draft_schedules` 或内存/临时表存预览方案（简化版可用 session 级不落库预览） |

**与老师意见关联**：多选订单、按条件指定调度（老师意见 2）。

---

### P1-04 · 地图显示

**现状**：路线为 **白底 SVG + Haversine 坐标**，无真实地图底图。

**目标**（可分步做）：

| 场景 | 说明 |
| --- | --- |
| **全局调度方案** | 在地图（如高德）上展示选中方案：节点名称、货物/路径概览 |
| **节点间调度** | 展示包裹信息与路径 |
| **路径可视化** | F010 增强：接入地图 API 或仍做静态叠加（需评估 Key 与配额） |

**执行要点**：

| 端 | 内容 |
| --- | --- |
| 后端 | `amap_service`（可选）；`GET /api/map/route` 返回 GeoJSON/坐标；地址 geocode |
| 前端 | 高德 JS SDK；方案/批次/车辆图层；与现有 SVG 并存或逐步替换 |
| 配置 | `.env` 配置 `AMAP_KEY`；见 [环境配置说明.md](./环境配置说明.md) 扩展 |

**与老师意见关联**：打包后在地图查看路线和位置（老师意见 5）。

**备注**：工作量和环境依赖较大；可先 **静态点位 + 折线**，再考虑动态轨迹（F011）。

---

### P1-05 · 全局方案评分数值处理

**现状**：全局方案 **score 等数值偏大**，展示不直观。

**目标**：评分可读、可对比（归一化、单位说明或换算法展示）。

**执行要点**：

| 端 | 内容 |
| --- | --- |
| 后端 | 检查 F007 评分公式与返回字段；必要时 scale / 保留小数 / 分项得分 |
| 前端 | 列表与详情统一格式化；tooltip 说明含义 |

**工作量**：小；建议与 P1-06 一并调整展示层。

---

### P1-06 · 全局方案：货物路径板块优化

**现状**：货物路径可能 **全量平铺**，信息量大；节点仅显示代码（如 SC005），缺少名称与关联订单/货物详情。

**目标**：与 **方案包裹一览** 交互一致：

- 下拉/折叠列表，非全部展开
- **搜索**（货物编号、订单号、节点等）
- 点击可查看详情：货物内容、所属订单、路径节点 **SC005 → 实际分拣中心名称**

**执行要点**：

| 端 | 内容 |
| --- | --- |
| 前端 | 复用包裹一览组件模式；搜索过滤；详情抽屉/弹窗 |
| 后端 | 确保接口返回节点 `name`、货物 `description`、订单关联字段（不足则扩展 DTO） |

---

### P1-07 · 节点间调度：列表与详情优化

**现状**：节点间调度列表/路径展示方式与全局方案类似，缺少结构化浏览。

**目标**：

- 调度编号 **下拉/折叠** 列表
- **搜索** 调度编号、车辆、包裹
- 查看 **单条调度详情**（任务、包裹、路径段）

**执行要点**：与 P1-06 前端模式复用；对接现有 `node_dispatches`、`dispatch_batches` API，必要时补 detail 聚合接口。

---

### P1-08 · 异常处理：包裹级编辑与单包裹重规划

**现状**：异常以 **事件级** 录入为主（节点/路线/批次），重规划多为整方案级；缺少 **指定哪些包裹出问题** 的细粒度操作。

**目标**：

1. **新页面或增强页**：手动勾选/编辑 **出问题的包裹**。
2. **单包裹异常处理**：处理后可进入 **新方案**（局部 replan 或引导全局/节点间重规划）。

**执行要点**：

| 端 | 内容 |
| --- | --- |
| 后端 | 扩展 `exception_events` 关联 `package_code`；单包裹异常 API；replan 范围参数 |
| 前端 | 包裹多选 + 异常类型；处理向导；结果跳转新 `schedule_code` |
| 与 P0 关系 | 在现有 `ExceptionList` + F013 上扩展，不重做核心 replan |

**与老师意见关联**：分用户确认送达时「有问题则异常录入」（老师意见 6）可与此联动。

---

### P1-09 · 订单 / 地址：物理地址与代码展示

**老师意见**：

1. 订单新增时，**目的地带上实际物理地址**。
3. 地址/节点 **代码旁显示实际地址或名称**（如 SC005 → 「华中分拣中心」）。

**执行要点**：

| 端 | 内容 |
| --- | --- |
| 数据 | `orders` / `sorting_centers` 等表是否已有 `address` 字段；无则 migration |
| 后端 | CRUD 与调度 DTO 带出 `address`、`display_name` |
| 前端 | 表单增加地址输入；列表/下拉/地图 label 双行展示「代码 + 地址」 |

---

### P1-10 · 实体编号可点击查看详情页

**老师意见**：货物、订单、车辆、节点等 **显示编号的同时可点进详情页**。

**现状**：部分列表仅有 code，详情页不完整或入口 hidden。

**执行要点**：

- 统一 `DetailDrawer` / 路由 `/orders/:code` 等
- 列表、调度方案、异常页中的 code 改为链接
- 可与 [前端迭代方向](./MVP开发计划-前端.md) 中「详情 UI」合并规划

---

### P1-11 · 分角色确认送达（运单号 + 异常录入）

**老师意见**：**单独菜单**；输入 **运单号** 确认送达；有问题则 **异常输入**。

**现状**：F013-1 模拟送达在调度流程内，偏演示向。

**目标**：

- 独立「确认送达」页面（可按角色区分 dispatcher / 现场操作员）
- 运单号查询 → 确认 → 更新状态
- 失败/异常分支跳转 P1-08 异常流程

**执行要点**：复用 `POST /api/simulation/deliver` 或扩展；前端新菜单项 + 表单。

---

### P1-12 · 权限 / 契约补齐

**来源**：阶段 8 联调。

| 项 | 说明 |
| --- | --- |
| `POST /api/ai/parse` | 执行调度应对 **dispatcher**；manager 可读 explain/review，不可执行 parse |
| 其它 RBAC | 按各阶段联调反馈逐项关闭 |

**工作量**：小；建议与其它 P1 第一批合并。

---

### P1-13 · 模拟送达增强

**来源**：API 契约 phase6（P1 标注）。

| 接口 | 说明 |
| --- | --- |
| `GET /api/simulation/status/{batch_code}` | 批次送达进度 |
| `POST /api/simulation/deliver-batch` | 一键送达整批 |

**价值**：减少演示重复点击；可与 P1-11 整合设计。
