## 1. 功能概述

### 1.1 背景

MVP 阶段的全局调度（`POST /api/schedule/global`）为**直接落库模式**：
- 调用即执行 F007 + F021
- 订单状态 `pending → delivering`
- 包裹 `pending_pack → packed`
- **无预览能力**，用户无法在落库前查看调度方案

### 1.2 目标

支持**预览 → 确认**两步流：
1. **预览模式**：生成调度方案（F007），仅存 `global_schedules`（status=draft），**不改**订单/货物/包裹状态
2. **确认模式**：用户确认后，执行完整 F007 + F021 落库流程（与 MVP 一致）

### 1.3 范围

| 做 | 不做 |
| --- | --- |
| `global_schedules` 新增 `status` 字段（draft/active） | 地图预览（P1-04） |
| `POST /api/schedule/global` 扩展 `preview` 参数 | 方案对比（P1-15） |
| `POST /api/schedule/confirm/{schedule_code}` 确认接口 | AI 解释（P1-01） |
| `DELETE /api/schedule/draft/{schedule_code}` 丢弃 draft |  |
| 列表接口默认过滤 draft |  |

## 2. API 契约

### 2.1 预览调度方案

**接口**：`POST /api/schedule/global`  
**描述**：生成调度方案预览（F007），写入 `global_schedules`（status=draft），不执行 F021，不改订单/货物状态。

#### Request Body

```json
{
  "order_codes": ["O001", "O002"],  // 可选；不传则自动筛选 status=pending 订单
  "algorithm": "traditional",         // 可选，默认 traditional
  "preview": true                    // ✅ 新增：预览模式
}
```

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `order_codes` | `List[str]` | 否 | 订单编号列表；不传则处理所有 `status=pending` 订单 |
| `algorithm` | `str` | 否 | 算法类型，默认 `traditional` |
| `preview` | `bool` | 否 | `true`=预览模式；不传或 `false`=直接落库（MVP 兼容，**本期移除**） |

> ⚠️ **P1-2  breaking change**：不再支持无 `preview` 参数的直接落库。前端必须先 preview → confirm。

#### Response（成功）

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "schedule_code": "GS20260624001",
    "total_distance": 1234.5,
    "total_time": 23.5,
    "total_goods": 15,
    "score": 567.8,
    "score_display": 85,
    "goods_schedules": [
      {
        "goods_code": "G001",
        "order_code": "O001",

          {"node_code": "SC001", "node_name": "华中存储中心"},

          {"node_code": "SO027", "node_name": "南区0级分拣中心"}
        ]
      }
    ],
    "status": "draft"
  },
  "meta": {
    "degraded": false,
    "degraded_reason": null
  }
}
```


## 4. 服务层改造

### 4.1 `ScheduleService.create_global_schedule`（改造）

**文件**：`src/backend/services/schedule_service.py`

#### 变更点

1. **新增 `preview: bool = False` 参数**
2. **preview=True 时**：
   - 执行 F007（全局调度算法）
   - 写入 `global_schedules`（status=draft）
   - **不执行** F021
   - **不更新** 订单/货物状态
   - **不提交** packages
   - 返回方案详情 + `status: "draft"`
3. **preview=False 时**（MVP 原逻辑）：
   - 执行 F007 + F021
   - 写入 `global_schedules`（status=active）
   - 更新订单/货物/包裹状态
   - 返回完整结果

#### 伪代码

```python
@staticmethod
async def create_global_schedule(
    order_codes: Optional[List[str]],
    algorithm: str,
    db: Session,
    preview: bool = False,  # ✅ 新增
    ...
) -> Dict[str, Any]:
    # 1. 检查是否已有 active 方案（order_codes 去重后无变化）
    if preview:
        existing = db.query(GlobalSchedule).filter(
            GlobalSchedule.status == "active",
            GlobalSchedule.order_codes.cast(str).like(f"%{order_codes[0]}%")
        ).first()
        if existing:
            return error_response(code=40002, message="已有活跃方案...")
    
    # 2. 执行 F007（纯计算）
    schedule_result = global_schedule(order_codes, algorithm, db, ...)
    
    if preview:
        # 3a. preview 模式：仅存 global_schedules（status=draft）
        global_schedule_obj = GlobalSchedule(
            ...,
            status="draft",  # ✅ 新增
        )
        db.add(global_schedule_obj)
        db.commit()
        
        return success_response(data={
            "schedule_code": schedule_result["schedule_code"],
            "status": "draft",
            # ... 其他字段
        })
    else:
        # 3b. 确认模式：执行 F021 + 状态更新（MVP 原逻辑）
        packages = packaging(schedule_result, None, db, ...)
        # ... 写入 packages + 更新状态
        global_schedule_obj.status = "active"  # ✅ 新增
        db.commit()
        
        return success_response(data={...})
```

### 4.2 `ScheduleService.confirm_schedule`（新增）

**文件**：`src/backend/services/schedule_service.py`

#### 流程

1. 查询 `global_schedules` 中 `status=draft` 且 `schedule_code={code}` 的记录
2. **校验订单状态**：确认所有 `order_codes` 中的订单仍为 `pending`（或 `exception` 重规划）
   - 若有变化，返回错误 `40003`，**删除 draft**
3. 执行 F021（打包算法）
4. 写入 `packages` 表
5. 更新订单状态 `pending → delivering`
6. 更新货物状态 `pending_pack → packed`
7. 更新包裹状态 `pending_pack → packed`
8. 更新 `global_schedules.status = active`
9. `db.commit()`

#### 伪代码

```python
@staticmethod
async def confirm_schedule(
    schedule_code: str,
    db: Session,
) -> Dict[str, Any]:
    # 1. 查询 draft 方案
    gs = db.query(GlobalSchedule).filter(
        GlobalSchedule.schedule_code == schedule_code,
        GlobalSchedule.status == "draft",
    ).first()
    if not gs:
        return error_response(code=40401, message="draft 方案不存在或已确认")
    
    try:
        # 2. 校验订单状态
        orders = db.query(Order).filter(
            Order.order_code.in_(gs.order_codes)
        ).all()
        for order in orders:
            if order.status not in ("pending", "exception"):
                # 删除 draft
                db.delete(gs)
                db.commit()
                return error_response(
                    code=40003,
                    message=f"订单 {order.order_code} 状态已变化（当前: {order.status}），请重新预览"
                )
        
        # 3. 执行 F021
        schedule_result = {
            "schedule_code": gs.schedule_code,
            "order_codes": gs.order_codes,
            "goods_schedules": gs.goods_schedules,
            "total_distance": gs.total_distance,
            "total_time": gs.total_time,
            "total_goods": gs.total_goods,
            "score": gs.score,
        }
        packages = packaging(schedule_result, gs.id, db, is_replan=(orders[0].status == "exception"))
        
        # 4. 写入 packages
        for pkg in packages:
            pkg.schedule_id = gs.id
            db.add(pkg)
        
        # 5. 更新状态（调用 state_machine）
        update_orders_after_f007(db, gs.order_codes)
        update_goods_after_f021(db, gs.id, is_replan=(orders[0].status == "exception"))
        
        # 6. 更新 status = active
        gs.status = "active"
        
        db.commit()
        
        return success_response(data={
            "schedule_code": gs.schedule_code,
            "status": "active",
            # ... 其他字段
        })
        
    except Exception as e:
        db.rollback()
        # 删除 draft
        db.delete(gs)
        db.commit()
        return error_response(code=50001, message=f"确认失败，draft 已丢弃: {str(e)}")
```

### 4.3 `ScheduleService.discard_draft`（新增）

**文件**：`src/backend/services/schedule_service.py`

#### 流程

1. 查询 `global_schedules` 中 `status=draft` 且 `schedule_code={code}` 的记录
2. 删除记录（物理删除）

#### 伪代码

```python
@staticmethod
async def discard_draft(
    schedule_code: str,
    db: Session,
) -> Dict[str, Any]:
    gs = db.query(GlobalSchedule).filter(
        GlobalSchedule.schedule_code == schedule_code,
        GlobalSchedule.status == "draft",
    ).first()
    if not gs:
        return error_response(code=40401, message="draft 方案不存在或已确认")
    
    db.delete(gs)
    db.commit()
    
    return success_response(data={
        "schedule_code": schedule_code,
        "status": "discarded",
    })
```

```python
        algorithm=body.algorithm,
        db=db,

    """
    丢弃 draft 调度方案
    
    需要角色：dispatcher
    """
    return await ScheduleService.discard_draft(
        schedule_code=schedule_code,
        db=db,
    )
```

## 8. 风险评估

| 风险 | 影响 | 缓解措施 |
| --- | --- | --- |
| preview 后订单状态被修改 | confirm 失败 | 已设计：校验订单状态，失败则删除 draft |
| draft 方案堆积 | 数据库膨胀 | 允许用户手动丢弃；可后续增加定时清理 |
| 前端未同步改造 | 功能不可用 | 必须与前端联调，不可单独上线 |
