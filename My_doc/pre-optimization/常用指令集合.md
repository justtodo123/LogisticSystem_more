## 8. 订单/货物/包裹状态流转表

| 步骤             | 触发方式 (demo_mode=false) | 触发方式 (demo_mode=true) | 触发条件           | 订单状态                | 货物状态                          | 包裹状态                          | 调度批次状态         |
|------------------|---------------------------|---------------------------|--------------------|-------------------------|-----------------------------------|-----------------------------------|---------------------|
| F007+F021完成    | 用户手动(1次API)          | 用户手动(1次API)          | 全局调度+打包完成  | `pending` → `delivering` | `pending_pack` → `packed`        | `pending_pack` → `packed`         | -                   |
| F005第一次调用   | 用户手动                   | 系统自动                   | L0→L1分配车辆      | `delivering`（不变）| `packed` → `in_transit`           | `packed` → `in_transit`           | `pending`           |
| 模拟送达第一次调用 | 用户手动                   | 系统自动                   | L0→L1送达          | `delivering`（不变）| `in_transit` → `pending_pack`     | `in_transit` → `delivered`         | `pending` → `l0_l1_done` |
| F021重新打包     | 用户手动                   | 系统自动                   | L1→L2打包          | `delivering`（不变）| `pending_pack` → `packed`         | 新包裹 `pending_pack` → `packed`   | `l0_l1_done`（不变） |
| F005第二次调用   | 用户手动                   | 系统自动                   | L1→L2分配车辆      | `delivering`（不变）| `packed` → `in_transit`                | `packed` → `in_transit`           | `l0_l1_done` → `completed` |
| 模拟送达第二次调用 | 用户手动                   | 系统自动                   | L1→L2送达          | `delivering`→`completed`| `in_transit` → `delivered`     | `in_transit` → `delivered`         | `completed`（不变）|


**说明**：
1. **触发方式列**明确了每个步骤是用户手动触发还是系统自动触发
2. **demo_mode=false**（生产模式）：所有步骤都需要用户手动触发
3. **demo_mode=true**（演示模式）：只需要用户手动触发2次API调用
   - 第1次：`POST /api/schedule/global` (自动完成F007+F021)
   - 第2次：`POST /api/schedule/node-dispatch?demo_mode=true` (自动完成F005第一次 + 模拟送达第一次 + F021重新打包 + F005第二次 + 模拟送达第二次)
- F005第一次调用 (存在包裹未分配)-> 模拟送达（L0→L1）-> 重新调度 -> 模拟送达（新分配的包裹）;
  这是在两个节点间调度出现包裹未分配的情况的处理逻辑，即不论包裹未分配的情况是出现在L0->L1,还是L1->L2，都是这样处理：
- 示例：（L1节点由于存在过多包裹而出现了未分配包裹）：F007完成（出现全局调度方案）-> F021完成 L0打包完成 （L0节点中货物打成包裹） -> F005第一次调用（L0节点中包裹与车辆匹配）-> 模拟送达第一次调用 -> F021重新打包(运算到L1节点中货物打成包裹，此时包裹数量众多) -> F005第二次调用（由于包裹数量众多，出现未分配包裹） -> 模拟送达第二次调用	(将L1节点中分配的包裹运送到L2节点) ->  F005第三次调用（由于包裹数量众多，此时依据有未分配包裹）->模拟送达第三次调用	(将L1节点中分配的包裹运送到L2节点) -> F005第三次调用（此时L1节点不存在未分配包裹）->模拟送达第三次调用	(将L1节点中分配的包裹运送到L2节点，此时全部运完 ，订单状态delivering→completed) 

### 1. 课堂演示/快速展示（使用 demo_mode=True）

> ⚠️ **前置条件**：
> - 必须使用**全新初始化的数据库**（先删库 → 重新建表 → init_demo_data）
> - 或者确保前一轮调度的车辆状态已通过模拟送达恢复为 `idle`
> - 若存储中心（L0）没有空闲车辆，L0→L1 调度将失败 → 包裹无法分配 → 订单无法完成

1. 登录系统（dispatcher/123456）

2. 创建订单
   POST /api/orders
   {
     "goods": [{"name": "商品A", "weight": 10, "quantity": 2}]
   }

3. 一键全局调度（F007+F021）
   POST /api/schedule/global
   {
     "order_codes": ["O001"],
     "algorithm": "traditional"
   }
   → 返回：{"schedule_code": "GS20260617001"}
   → 状态变更：订单 pending→delivering, 货物 pending_pack→packed, 包裹 pending_pack→packed

4. 一键节点调度 + 路径规划（F005+F006，demo_mode=True）
   POST /api/schedule/node-dispatch
   {
     "schedule_code": "GS20260617001",
     "demo_mode": true
   }
   → 尝试自动完成：
     - L0→L1 调度（从存储中心分配车辆）
     - 模拟送达（L0→L1）：包裹 in_transit→delivered, 货物 in_transit→pending_pack
     - L1 重新打包：货物 pending_pack→packed, 生成新 L1→L2 包裹
     - L1→L2 调度（从L1分拣中心分配车辆）
     - 模拟送达（L1→L2）：包裹 in_transit→delivered, 货物 in_transit→delivered, 订单 delivering→completed
   → 返回：{"batch_code": "BATCH20260617001", "status": "completed"}

   **⚠️ 期望结果**（仅在 L0→L1 调度成功的条件下）：
   - 订单状态：全部 `completed`
   - 货物状态：全部 `delivered`
   - 包裹状态：全部 `delivered`
   - 车辆状态：全部 `idle`
   - 司机状态：全部 `idle`

   **⚠️ 常见问题**：
   - 如果 L0→L1 调度失败（存储中心无空闲车辆），则会出现：
     - unallocated_packages 列表不为空
     - 部分货物/包裹保持 `packed` 状态
     - 订单保持 `delivering`（因为 order_codes 为空，无订单被标记 completed）
   - **解决方案**：重新初始化数据库（删除 logistics.db → alembic upgrade head → init_demo_data → run_tests）

5. 查看完整路线（阶段5，当前未实现）
   GET /api/routes/by-vehicle/VEH001/coordinates
   → 返回路线图坐标


### 2. 真实生产环境（使用 demo_mode=False）
1. 登录系统

2. 创建订单 + 全局调度（同场景1的步骤1-3）

3. 第一次节点调度（L0→L1，demo_mode=False）
   ```
   POST /api/schedule/node-dispatch
   {
     "schedule_code": "GS20260617001",
     "demo_mode": false
   }
   ```
   → 只完成 L0→L1 调度
   → 返回：{"batch_code": "BATCH20260617001", "status": "l0_l1_done"}

4. 等待实际送达（L0→L1）
   - 司机驾驶车辆从 L0 到 L1
   - 到达后，调度员调用：
   
   ```
   POST /api/simulation/deliver
   {
     "vehicle_code": "VEH001",
     "package_code": null  # 送达该车辆所有包裹
   }
   ```
   → 更新包裹状态：in_transit → delivered
   → 更新货物状态：in_transit → pending_pack
   → **系统自动触发**：F021重新打包（L1→L2）
   → **系统自动触发**：第二次F005（L1→L2调度，异步执行）
   → 返回：{"auto_triggered": {"repackaging": true, "second_f005": true}}

5. 等待第二次F005完成 + 实际送达（L1→L2）
   - 系统异步执行第二次F005
   - 司机驾驶车辆从 L1 到 L2
   - 到达后，调度员调用：
   
   ```
   POST /api/simulation/deliver
   {
     "vehicle_code": "VEH002",
     "package_code": null
   }
   ```
   → 更新包裹状态：in_transit → delivered
   → 更新货物状态：in_transit → delivered
   → 更新订单状态：delivering → completed
   → **系统自动触发**：重新调度未分配包裹（如果有）

6. 查看完整路线
   ```
   GET /api/routes/by-vehicle/VEH001/coordinates
   ```
