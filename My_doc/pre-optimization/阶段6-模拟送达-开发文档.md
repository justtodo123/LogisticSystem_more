# 阶段6（模拟送达 F013-1）开发文档

## 1. 文档概述

### 1.1 文档目的
本文档详细描述阶段6（模拟送达 F013-1）的开发需求、API设计、自动触发逻辑和测试步骤。

**两种模式的行为差异**：
1. **demo_mode=true**（演示模式）：
   - 在阶段4已实现：一次API调用自动完成所有步骤
   - 不需要阶段6的自动触发逻辑

2. **demo_mode=false**（生产模式）：
   - 需要阶段6的自动触发逻辑来支持完整流程
   - 第一次送达（L0→L1）完成后，系统自动检测 `pending_pack` 货物
   - 系统自动执行F021重新打包
   - 系统自动执行第二次F005（L1→L2调度，异步执行）
   - 详见本文档 §2.2 自动触发逻辑

3. **自动重新调度功能**（阶段6新增）：
   - 模拟送达后，系统自动检测未分配的包裹
   - 如果有空闲车辆，自动重新调度未分配包裹
   - 支持递归重新调度（多次循环，直到没有新分配或没有空闲车辆）
   - 详见本文档 §2.3 自动重新调度逻辑

阶段6需要为 `demo_mode=false` 模式实现完整的流程支持，并新增自动重新调度功能。

## 2. 核心流程设计

### 2.1 `demo_mode=false` 完整流程

```
用户调用 POST /api/schedule/node-dispatch (demo_mode=false)
    ↓
系统执行L0→L1调度 → 返回 batch_code + status=l0_l1_done
    ↓
用户调用 POST /api/simulation/deliver (vehicle_code或package_code)
    ↓
系统执行L0→L1送达：
  - 包裹状态：in_transit → delivered
  - 货物状态：in_transit → pending_pack（如果未到目的地）
  - 车辆状态：delivering → idle（如果所有包裹已送达）
  - 司机状态：busy → idle（如果车辆变idle）
    ↓
系统自动检测 pending_pack 货物 → 执行F021重新打包
  - 货物状态：pending_pack → packed
  - 生成新包裹（L1→L2）
    ↓
系统自动执行第二次F005（L1→L2调度，异步执行）
  - 批次状态：l0_l1_done → completed（异步更新）
    ↓
系统自动检测未分配包裹 → 执行自动重新调度（递归）
  - 如果有空闲车辆，重新调度未分配包裹
  - 支持递归重新调度（多次循环）
    ↓
用户轮询 GET /api/schedule/batches/{batch_code} 查看状态
    ↓
用户调用 POST /api/simulation/deliver (第二次送达，L1→L2)
    ↓
系统执行L1→L2送达：
  - 包裹状态：in_transit → delivered
  - 货物状态：in_transit → delivered（如果到达目的地）
  - 订单状态：delivering → completed（如果所有货物已送达）
```

### 2.2 自动触发逻辑

#### 2.2.1 自动触发L1重新打包

**触发时机**：`POST /api/simulation/deliver` 执行完成后

**检测条件**：
- 检查是否有 `pending_pack` 状态的货物
- 这些货物必须满足：`goods.node_id` 是L1分拣中心（即L0→L1已送达）

**执行逻辑**：
```python
# 在 simulation_service.py 的 deliver_packages() 方法末尾添加
def deliver_packages(...):
    # ...  existing delivery logic ...
    
    # 自动触发L1重新打包
    pending_pack_goods = db.query(Goods).filter(
        Goods.status == 'pending_pack',
        Goods.node_id.in_([node.id for node in l1_nodes])
    ).all()
    
    if pending_pack_goods:
        # 调用F021重新打包算法
        from algorithms.packaging import run_packaging
        run_packaging(db, schedule_code, is_repack=True)
        
        # 自动触发第二次F005（异步）
        trigger_second_f005(db, batch_code)
```

#### 2.2.2 自动触发第二次F005

**触发时机**：F021重新打包完成后

**执行方式**：异步执行（不阻塞送达API响应）

**实现方案**：
```python
import asyncio
from concurrent.futures import ThreadPoolExecutor

def trigger_second_f005(db: Session, batch_code: str):
    """触发第二次F005（异步执行）"""
    # 在新线程中执行，避免阻塞API响应
    executor = ThreadPoolExecutor(max_workers=1)
    executor.submit(_execute_second_f005, db, batch_code)

def _execute_second_f005(db: Session, batch_code: str):
    """执行第二次F005"""
    try:
        # 调用F005算法（L1→L2）
        from algorithms.node_dispatch import run_node_dispatch
        result = run_node_dispatch(
            db, 
            schedule_code, 
            demo_mode=False, 
            is_second_call=True  # 标识第二次调用
        )
        
        # 更新批次状态为 completed
        batch = db.query(DispatchBatch).filter(
            DispatchBatch.batch_code == batch_code
        ).first()
        if batch:
            batch.status = 'completed'
            db.commit()
            
    except Exception as e:
        # 记录错误日志，但不影响第一次送达的结果
        print(f"第二次F005执行失败：{e}")
```

**状态查询**：用户通过 `GET /api/schedule/batches/{batch_code}` 轮询状态
- `status=l0_l1_done`：第二次F005正在执行
- `status=completed`：第二次F005执行完成

## 3. API设计

### 3.1 POST /api/simulation/deliver

**功能**：模拟包裹送达操作，驱动状态流转

**认证**：Bearer Token (dispatcher角色)

**请求体**：
```json
{
  "vehicle_code": "xxx",  // 可选，车辆编号
  "package_code": "xxx"   // 可选，包裹编号
}
```

**参数组合逻辑**：
- 无参数：处理所有 `in_transit` 包裹
- 仅 `vehicle_code`：处理该车辆所有 `in_transit` 包裹
- 仅 `package_code`：处理指定包裹（必须 `in_transit` 状态）
- 都传：处理指定车辆的指定包裹（必须 `in_transit` 状态）

**响应数据**：
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "delivered_package_codes": ["PKG001", "PKG002"],
    "status_changed_goods_count": 5,
    "updated_order_count": 1,
    "delivered_order_codes": ["O001"],
    "auto_triggered": {
      "repackaging": true,  // 是否自动触发了重新打包
      "second_f005": true    // 是否自动触发了第二次F005
    }
  },
  "meta": {
    "degraded": false,
    "degraded_reason": null
  }
}
```

**自动触发说明**：
- 如果送达后检测到 `pending_pack` 货物，系统会自动执行F021重新打包
- 如果重新打包完成，系统会自动触发第二次F005（异步执行）
- 响应中的 `auto_triggered` 字段告知用户系统自动执行了哪些操作

## 4. 状态流转规则

### 4.1 第一次送达（L0→L1）

| 实体 | 原状态 | 条件 | 新状态 |
|------|--------|------|--------|
| 包裹 | `in_transit` | 送达 | `delivered` |
| 货物 | `in_transit` | `goods.node_id == order.destination_node_id` | `delivered` |
| 货物 | `in_transit` | `goods.node_id != order.destination_node_id` | `pending_pack` |
| 车辆 | `delivering` | 车辆上所有包裹都送达 | `idle` |
| 司机 | `busy` | 车辆状态变为 `idle` | `idle` |
| 订单 | `delivering` | 订单所有货物都 `delivered` | `completed` |
| 批次 | `pending` | 第一次送达完成 | `l0_l1_done` |

### 4.2 自动重新打包（F021）

| 实体 | 原状态 | 条件 | 新状态 |
|------|--------|------|--------|
| 货物 | `pending_pack` | 重新打包完成 | `packed` |
| 包裹 | - | 生成新包裹（L1→L2） | `pending_pack` → `packed` |

### 4.3 第二次送达（L1→L2）

| 实体 | 原状态 | 条件 | 新状态 |
|------|--------|------|--------|
| 包裹 | `in_transit` | 送达 | `delivered` |
| 货物 | `in_transit` | `goods.node_id == order.destination_node_id` | `delivered` |
| 货物 | `in_transit` | `goods.node_id != order.destination_node_id` | `pending_pack`（理论上不应出现） |
| 车辆 | `delivering` | 车辆上所有包裹都送达 | `idle` |
| 司机 | `busy` | 车辆状态变为 `idle` | `idle` |
| 订单 | `delivering` | 订单所有货物都 `delivered` | `completed` |
| 批次 | `l0_l1_done` | 第二次送达完成 | `completed` |
