# 智能物流平台 · 前端演示操作指南

> **适用场景**：答辩 / 课堂演示 / 验收评审  
> **演示角色**：dispatcher（调度员，具备全部操作权限）  
> **预计时长**：~15-20 分钟（含讲解）  
> **演示路径**：登录 → 基础数据 → 全局调度 → 节点间调度 → 路径规划可视化 → 模拟送达 → 到货确认 → 异常管理 → AI 助手

---

## ⚠️ 演示前准备

### 1. 启动后端
```bash
cd src/backend
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

### 2. 初始化演示数据（首次或重置时执行）
```bash
cd src/backend
python scripts/init_demo_data.py
```

### 3. 启动前端
```bash
cd src/frontend
npm install
npm run dev                    # http://localhost:5173
```

### 4. 确认环境
- 浏览器打开 `http://localhost:5173` → 应自动跳转 `/login`
- 浏览器打开 `http://localhost:8000/docs` → 确认后端 Swagger 文档可访问

## 🚀 演示步骤（完整流程）

### 第 1 步：登录（~30s）

| 操作 | 说明 |
|------|------|
| 打开 `http://localhost:5173` | 自动跳转到 `/login` |
| 输入用户名 `dispatcher` | 调度员角色，具备全部操作权限 |
| 输入密码 `123456` | Mock 预置密码 |
| 点击「登录」 | 登录成功跳转 `/dashboard` |

**讲解要点**：
- 系统支持两种角色：`dispatcher` 写权限 / `manager` 只读权限
- JWT 认证，24 小时过期
- 登录页猫头鹰动画（聚焦密码框时闭眼）可作为趣味开场

### 第 2 步：基础数据概览（~2 min）★可选快览

> 如果演示数据已预置，可快速浏览跳过。如需展示 CRUD 能力则重点演示订单创建。

#### 2.1 存储中心（`/nodes/storage`）
- 侧栏点击「存储中心」→ 查看 5 个 L0 存储中心（SC001-SC005）
- 点击详情可查看名称、经纬度、容量

#### 2.2 分拣中心（`/nodes/sorting`）
- 侧栏点击「分拣中心」→ 查看 1 级分拣中心（L1 如 SO001）和 0 级分拣中心（L2 如 SO027）
- 注意层级区分：1 级是转运枢纽，0 级是最终目的地

#### 2.3 车辆管理（`/vehicles`）
- 查看 70 辆车（7 个节点 × 10 辆），注意车辆归属节点和状态

#### 2.4 ★演示：手动创建订单（重点）
- 侧栏点击「订单管理」→ 点击右上角「新增订单」
- 填写订单信息：
  - 订单编号：如 `DEMO-001`
  - 寄件人 / 收件人：张三 → 李四
  - 起始节点：选择一个存储中心（如 SC001）
  - 目的节点：选择一个 0 级分拣中心（如 SO027）
  - 添加货物明细：货物品名、数量、重量
- 保存后订单状态为 `pending`

> 💡 **快速方案**：使用 Excel 批量导入功能，上传 `orderdata.xlsx`（项目根目录有模板）

---

### 第 3 步：全局调度 ★核心演示（~3 min）

> 这是系统最核心的业务流程，包含 F007 全局调度 + F021 打包。

#### 3.1 选择订单并生成预览
| 操作 | 说明 |
|------|------|
| 进入 `/dashboard` | 调度工作台页面 |
| 在左侧「订单选择面板」勾选 pending 订单 | 可多选，或点击"全选" |
| 点击「**生成预览**」按钮 | 触发 F007 全局调度算法 |

**观察现象**：
- 按钮变为 loading 状态（防重复点击）
- 生成完成后弹出「方案摘要卡片」：总订单数、包裹数、车辆数、覆盖节点数
- 下方「货物路径表」展示每条货物 L0→L1→L2 的完整路径

#### 3.2 确认采用方案
| 操作 | 说明 |
|------|------|
| 查看货物路径表 | 确认调度结果合理 |
| 点击「**确认采用**」 | 方案落库，orders 状态 `pending` → `delivering` |

**讲解要点**：
- F007 算法评分公式：`score = w1×总距离 + w2×总时间 + w3×包裹数`
- F021 打包逻辑：L0→L1 按节点对合并，L1→L2 按同订单合并
- 确定性算法，同输入必然同输出

#### 3.3 （可选）AI 助手面板
- 点击右侧「AI 助手」标签
- 可输入自然语言如「把 SC001 的订单优先配送」→ 调用 DeepSeek API 解析
- 点击「解释当前方案」→ AI 用自然语言解读调度结果

---

### 第 4 步：节点间调度（~2 min）

| 操作 | 说明 |
|------|------|
| 向下滚动到「节点间调度」面板 | DispatchBatchPanel 组件 |
| ✅ 勾选「**演示模式**」 | demo_mode=true，跳过 L1 实际送达等待 |
| 点击「**生成节点间调度**」 | 触发 F005 两次串行 |

**观察现象**：
- 第一次 F005（L0→L1）：分配车辆 → 生成 `level_phase=0` 的 dispatch 记录
- 第二次 F005（L1→L2）：分配车辆 → 生成 `level_phase=1` 的 dispatch 记录
- 「车辆任务表」展示每辆车的任务明细（from → to 节点、包裹列表）

**讲解要点**：
- F005 串行依赖：L0→L1 失败则整个批次失败
- demo_mode 绕过 L1 实际送达，课堂演示必备
- 司机分配策略：从车辆归属节点选第一个 idle 司机

---

### 第 5 步：路径规划与可视化 ★亮点演示（~3 min）

#### 5.1 路径规划
| 操作 | 说明 |
|------|------|
| 点击「**路径规划**」按钮 | 触发 F006 为每辆车规划路径 |
| 等待生成完成 | Haversine 距离计算 + 2-opt 路径优化 |

#### 5.2 路线可视化（RouteMap）
| 操作 | 说明 |
|------|------|
| 在「车辆路线选择器」选择一辆车 | 如车辆 VH-SC001-001 |
| SVG 地图上显示该车的完整路线 | 节点图标 + 连接线段 + 包裹标注 |
| **缩放操作**：鼠标滚轮 / 双指捏合 | SVG 缩放视图 |
| **全屏按钮**：点击全屏展示 | 适合投影/大屏演示 |
| 点击地图上的包裹节点 | 查看包裹详情弹窗 |

**讲解要点**：
- 纯 SVG 实现，不依赖任何地图 API（离线可演示）
- 虚拟城市坐标（中心 30.5°N, 114.3°E）
- F006 算法公式：`cost = w1×距离 + w2×时间 + w3×碳排放`
- 燃油车碳排放 = 里程 × 0.2 kg/km

---

### 第 6 步：模拟送达（~1 min）

| 操作 | 说明 |
|------|------|
| 在 Dashboard 中部找到「模拟送达」按钮 | 两种模式可选 |
| 点击「**全部送达**」 | 所有 `in_transit` 包裹 → `delivered` |
| 或点击「**当前车辆送达**」 | 仅当前选中车辆的包裹送达 |

**观察现象**：
- 车辆状态 `delivering` → `idle`
- 司机状态 `busy` → `idle`
- 包裹状态 `in_transit` → `delivered`
- 货物到达 L2 后状态变为 `delivered`

**讲解要点**：
- 所有状态变更统一走 `transition_*_status()` 方法
- 非法转换立即抛出 ValueError 拒绝
- 状态级联更新：送达一个包裹影响关联的订单/货物/车辆/司机

---

### 第 7 步：节点到货确认（~1.5 min）★P1 功能

| 操作 | 说明 |
|------|------|
| 侧栏点击「到货确认」 | 进入 `/arrival-confirm` 页面 |
| 选择一个调度方案 | 下拉选择 `schedule_code` |
| 选择一个 L1 分拣中心 | 如 SO001 |
| 点击「加载待确认包裹」 | 列出所有到达该节点的包裹 |
| 对每个包裹选择「正常确认」 | 绿色标签 |
| 对异常包裹选「异常确认」 | 红色标签（如包裹破损） |
| 点击「提交确认」 | 结果摘要弹窗 |

**观察现象**：
- 正常包裹：货物状态推进
- 异常包裹：红色高亮，级联激活下游相关包裹异常
- 结果摘要：正常数 / 异常数 / 级联数 / 关联货物状态

### 第 8 步：异常处理（~1.5 min）★P1 功能

| 操作 | 说明 |
|------|------|
| 侧栏点击「异常管理」 | 进入 `/exceptions` 页面 |
| 点击「录入异常」 | 弹出表单 |

#### 演示两种异常类型：

**场景 A：节点异常（触发 redispatch）**
| 字段 | 值 |
|------|-----|
| 异常类型 | 节点异常 |
| 异常子类型 | 容量上限 |
| 目标节点 | SO001 |
| 描述 | 1 级分拣中心容量已满 |

**场景 B：道路异常（触发 reroute）**
| 字段 | 值 |
|------|-----|
| 异常类型 | 道路异常 |
| 异常子类型 | 道路封闭 |
| 目标节点 | SC001 → SO001 |
| 描述 | 主干道施工封闭 |

#### 触发重规划
- 在异常列表中点击「重规划」按钮
- redispatch：重新执行 F007 + F005 + F006
- reroute：仅重新执行 F006 路径规划

**讲解要点**：
- 版本链机制：新方案 `version+1`，`parent_id` 指向前版，`is_replan=true`
- 原方案完整保留可对比
- 异常分为三类：road / package / node

## ❗ 常见演示问题与应对

| 问题 | 应对 |
|------|------|
| 后端未启动 | 前端列表页显示空数据；提示先 `uvicorn main:app` |
| 演示数据未初始化 | 执行 `python scripts/init_demo_data.py` 后刷新 |
| 调度按钮无反应 | 检查是否有 `pending` 状态订单；确认订单选中有 id |
| DeepSeek API 不可用 | 演示降级策略：UI 显示警告 `meta.degraded=true` |
| 路线图空白 | 确认已完成路径规划（F006），且选中了有任务的车辆 |
| 节点间调度失败 | 可能有包裹未打包；先执行全局调度 |
| 端口被占用 | `netstat -ano \| findstr :8000` / `:5173` 检查并 kill |
