## 三、技术实现方案

### 3.1 DeepSeek API调用

**模型选择**：`deepseek-chat`（V3版本）

**提示词设计**：
```python
SYSTEM_PROMPT = """你是一个物流调度专家。根据用户需求和当前系统状态，生成算法参数JSON。

你必须严格按照以下JSON格式输出：
{
  "global_schedule": {
    "algorithm": "traditional",
    "weights": {"distance": 0.5, "time": 0.3, "package_count": 0.2}
  },
  "node_dispatch": {
    "algorithm": "traditional",
    "weights": {"distance": 0.5, "time": 0.3, "package_count": 0.2}
  },
  "route_planning": {
    "algorithm": "traditional",
    "max_iterations": 1000
  }
}"""
```

**降级策略**：
- API调用超时（>30秒）→ 使用默认参数
- API返回错误 → 使用默认参数
- 返回格式错误 → 重试2次，仍失败则使用默认参数

**默认参数来源**：`config/default_algorithm_params.json`

### 3.2 /api/ai/parse接口

**请求体**：
```json
{
  "message": "请为当前待分配订单生成调度方案",
  "auto_execute": true
}
```

**响应体**：
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "schedule_code": "GS20260622001",
    "algorithm_params": {...}
  },
  "meta": {
    "degraded": false,
    "degraded_reason": null
  }
}
```

**执行逻辑**：
1. 获取系统上下文（订单数、车辆数、节点数）
2. 调用DeepSeek API解析自然语言
3. 如果DeepSeek失败，降级使用默认参数
4. 如果auto_execute=true，执行完整调度链路：
   - 调用F007全局调度
   - 调用F021打包服务
   - 调用F005节点间调度（demo_mode=true，连续执行L0→L1和L1→L2）
   - 调用F006路径规划
5. 记录埋点（deepseek_call事件）
6. 返回结果

### 3.3 log_events埋点

**event_data字段定义**：

| 事件名称 | event_data字段 |
|---------|--------------|
| login | `{ip, user_agent}` |
| logout | `{}` |
| global_schedule | `{schedule_code, order_count, algorithm_type}` |
| node_dispatch | `{batch_code, package_count, vehicle_count, algorithm_type}` |
| route_plan | `{route_count, vehicle_count}` |
| replan | `{event_code, reason, new_schedule_code}` |
| deepseek_call | `{function_name, success, degraded}` |

**实现方式**：在服务层方法上添加装饰器 `@auto_log(event_name)`

### 3.4 P1占位接口

```json
  "data": null,
  "meta": {"degraded": false, "degraded_reason": null}
}
```

## 七、风险与缓解

| 风险 | 缓解措施 |
|------|---------|
| DeepSeek API配额不足 | 提前申请足够配额，或准备多个API Key轮询 |
| DeepSeek API响应慢 | 设置30秒超时，超时自动降级 |
| 自然语言解析不准确 | 优化提示词，增加示例；解析失败时使用默认参数 |
| 埋点影响性能 | 异步写入，不阻塞主流程 |
