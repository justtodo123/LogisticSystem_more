## 五、P1 增强与扩展（2.0 min）

### Slide 9 — 异常处理与到货确认

- **左侧**：异常处理类型与重规划流程

| 异常类型 | 处理方式 | 示例 |
|----------|----------|------|
| 道路异常 | → reroute（仅重跑 F006） | 道路封闭，绕行 |
| 包裹异常 | → reroute | 包裹破损需重发 |
| 节点异常 | → redispatch（重跑 F007+F005+F006） | 分拣中心容量不足 |

- **右侧**：到货确认流程（P1-08 新增）

```
包裹到达 L1 → 正常确认 → 货物变 pending_pack → F021 重新打包 → 继续 L1→L2
包裹到达 L1 → 异常确认 → 货物变 exception → 记录异常事件
包裹到达 L2 → 正常确认 → 货物变 delivered → 订单完成
```

| 讲解要点 | 时间 |
|----------|------|
| 解释三种异常类型与两种处理方式（reroute vs redispatch） | 25s |
| 强调"版本化重规划"：version+1，parent_id 指向原方案，原版完整保留 | 15s |
| P1 到货确认：L1 正常确认后自动触发 F021 重打包，L2 确认后订单完成 | 20s |
| 状态流转的严密性：异常确认可将所有关联货物/包裹级联置 exception | 10s |

> **累计 9.0 min**
